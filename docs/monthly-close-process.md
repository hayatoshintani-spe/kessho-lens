# 月次決算プロセスの分解（Monthly Close Process Breakdown)

コンテンツ・IP ビジネス（ライセンス収益・MD・映像製作を含む）を前提とした、月次決算プロセスの標準的な分解ドキュメント。
「Kessho Lens」で月次決算の進捗・ボトルネックを可視化するための土台として、プロセスを **フェーズ → タスク → 担当 / インプット / アウトプット / 期日 / 依存関係** の粒度まで分解する。

> 期日表記: `D+n` = 月末営業日から n 営業日後（例: D+1 = 翌月第1営業日）。目標は **D+5 締め / D+7 報告** のクイッククロージング。

---

## 1. 目的とゴール

| 観点 | 内容 |
|---|---|
| スピード | 経営判断に間に合うタイミングで数値を確定する（D+5 締め / D+7 経営報告） |
| 正確性 | 発生主義に基づく網羅的な計上。試算表レベルでの検証を毎月実施 |
| 経営活用 | 予実差異・事業別損益・KPI と接続し、「見るための決算」から「動くための決算」へ |
| 年次決算の前倒し | 月次で論点を潰し、四半期・年次決算の負荷とリスクを平準化 |

## 4. クリティカルパスとボトルネック

典型的なクリティカルパスは以下の 2 本:

1. **原価ライン**: 仕入計上 (2-1) → 在庫評価 (3-2) → 原価計算 (3-3) → 試算表 (6-1) → 確定 (6-5)
2. **収益ライン**: ロイヤリティレポート回収 (1-2) → 収益計上 → 試算表 (6-1) → 確定 (6-5)

| ボトルネック | 典型原因 | 短縮化の打ち手 |
|---|---|---|
| ロイヤリティレポートの回収遅延 | ライセンシー側の報告サイクル | 見積計上ルールの標準化（過去実績×季節性）、翌月精算 |
| 経費精算の駆け込み | 締切意識の低さ | 週次精算への分散、法人カードの自動連携 |
| 請求書未着の未払計上 | 発注データと会計の分断 | 発注残からの自動未払計上 |
| 原価計算の手作業 | Excel 依存・配賦の複雑さ | 配賦ロジックの簡素化・システム化 |
| 増減分析のコメント収集 | 事業部への依頼が締め後 | 締め前に速報値ベースで依頼を先行 |

## 5. コントロール・チェックリスト（月次）

- [ ] 全銀行口座の残高照合が完了し、差異ゼロまたは説明済み
- [ ] AR / AP の補助簿残高と総勘定元帳が一致
- [ ] 経過勘定（未収・未払・前受・前払）の明細が最新化されている
- [ ] ロイヤリティ収益の見積計上分に根拠メモがある
- [ ] 在庫の帳簿残高と実地（または循環棚卸）の差異が処理済み
- [ ] 製作勘定・コンテンツ資産の償却が作品別スケジュール通り
- [ ] 引当金（貸倒・返品・賞与）の計算根拠が更新されている
- [ ] 消費税区分の異常値チェック（非課税・不課税の誤区分）が完了
- [ ] 前月比で ±10% 超の変動科目にコメントが付いている
- [ ] 会計期間がロックされ、確定後の仕訳追加ができない状態

## 6. データフロー（システム観点）

```
 販売管理 ──┐
 ライセンス管理 ─┤
 購買管理 ──┼──→ 会計システム（仕訳） ──→ 試算表 ──→ 月次報告 / ダッシュボード
 経費精算 ──┤          ↑
 給与計算 ──┤          │
 在庫・原価 ──┘    固定資産台帳・償却計算
```

Kessho Lens への展開案: 上記のタスク分解（Phase / タスク / 期日 / 依存関係）を構造化データとして持ち、
各月のクローズ進捗（完了 / 遅延 / ブロック）をカンバン形式で可視化し、遅延タスクとクリティカルパスへの影響を
自動でハイライトする——というのが本ドキュメントの次のステップとなる。

## 7. 用語集

| 用語 | 意味 |
|---|---|
| MG (Minimum Guarantee) | ライセンス契約における最低保証料 |
| RR (Running Royalty) | 売上高等に連動するランニングロイヤリティ |
| 経過勘定 | 未収収益・未払費用・前受収益・前払費用の総称 |
| 循環棚卸 | 全量一斉ではなく、対象を分割して定期的に行う棚卸 |
| クイッククロージング | 決算早期化。月次では D+3〜D+5 締めが一般的な目標 |
| 会計期間ロック | 確定後の月に仕訳を追加できないようにするシステム制御 |
