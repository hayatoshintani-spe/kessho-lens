## 集計ロジック定義テンプレート

各カテゴリについて以下を確定させる（質問票の回答項目に対応させる想定）:

1. **集計元データ**: どの帳票・システムから取るか（総勘定元帳／販売管理／案件管理 等）
2. **判定キー**: カテゴリを一意に決める項目（部門コード／セグメント／勘定科目／取引先／商品区分 のどれか、または組合せ）
3. **付与タイミング**: 仕訳起票時に付与済みか、月次で後付けの割り振りが必要か
4. **按分の有無**: 複数カテゴリに跨がる取引（例: 複合契約）の按分ルール
5. **「その他」の定義**: 明示的なタグなし＝その他、とするか、その他タグを能動的に付けるか
6. **例外処理**: 判定キーが欠損しているデータの扱い（サスペンス勘定に寄せる／担当者に差し戻す）

## 会計データ連携（Next Action 3）との関係

- 連携対象は **部門およびセグメント情報が付与された総勘定元帳データ**
- カテゴリ判定キーがGLの部門・セグメントだけで完結するなら追加作業は軽い。
  完結しない場合（取引先・商品区分が必要な場合）は、GL以外の補助データ連携または起票時のタグ付与運用が必要 → **質問票で最初に確定させるべき論点**

## 質問票回答時に社内で確認すること（要確認リスト）

- [ ] 各カテゴリの現行の集計方法（誰が・どの帳票で・どの粒度で集計しているか）
- [ ] GLの部門・セグメント体系でカテゴリがどこまで判別できるか（財務経理部）
- [ ] 複合案件・跨ぎ案件の按分実務の有無
- [ ] 「その他」に落ちている金額の規模感（その他が大きすぎるとダッシュボードの意味が薄れる）
- [ ] 地域別軸との交差（カテゴリ×地域のクロスが必要か、単軸でよいか）
