# プロジェクトのシンプル化方針（2026-07-16 決定）

**作成：新谷（STO）。本メモは既存の設計書群に優先する。矛盾する記述は次回改訂時に各設計書へ反映するが、運用は本日からこのメモに従う**
**背景：設計が充実した一方で、会議・資料・タスクが増えすぎた。専任1名＋兼務の実態に合わせ、動くものを絞る**

---

## 1. 動くものを3本に絞る（それ以外は「待ち」）

| # | いま動くもの | ゴール |
|---|---|---|
| 1 | **確認会**（部長ごと・主担当の確定） | 746社・299案件の主担当が全部埋まる |
| 2 | **財務ひも付け**（柳沼さんデータ×名寄せ） | 顧客・案件に金額が付く |
| 3 | **採点→力の入れ直し**（1・2の完了後） | ランクが決まり、資源配分を変え始める |

- この3本は一直線につながっている（担当→金額→採点）。**同時多発をやめ、この順で進める**
- **段階起動に変更するもの**：工数計測は確認会完了後に開始（当初Day1想定を変更。現場への同時負荷を避ける）。監修改革・接点KPI・地域戦略などの論点は分科会の器で扱うが、STOの手は3本が終わるまで出さない

## 2. 会議を最小で起動する

| 会議 | 変更 |
|---|---|
| 分科会×3 | **隔週45分でスタート**（週次75分の当初設計を変更。軌道に乗り、議題が溢れたら週次に戻す） |
| STO日次15分 | **廃止**。週2回15分（月・水）に変更（坪井さん兼務のため） |
| 金曜週次レビュー30分／戦略会議（隔週）／点検会議（月次） | 維持（ここは背骨） |

- 判断基準：**「決めることがない会議は開かない」を頻度にも適用する。** 立ち上げ期は議題が細いので、頻度を落として1回を濃くする
- 高橋さん・橋本さんの「会議を減らしてくれ」の声への回答でもある。改革自身が身を削るのが一番の説得力

## 3. 現場に配る資料を3つだけにする

1. **プロジェクト1枚**（新設。これが全員の共通言語）
2. **運用指南書**（自分の役割の章だけ読む）
3. **棚卸しマスター**（坪井さん管理の共有版）

- それ以外の50超のファイルは**STO内部の設計庫**（アーカイブ扱い）。求められたら出すが、こちらから配らない。正本管理は資料一覧で継続
- 新しい資料は「プロジェクト1枚の差し替え」で吸収し、**新規ファイルを増やさないことを原則にする**

## 4. ルールを3つだけにする（現場向け）

1. 工数・データは**評価に使わない**
2. いま決めるのは**主担当だけ**（役割メモは書ける範囲で）
3. 迷ったら**24時間以内に新谷へ**（抱えるより上げる）

受付5条件・L1〜L4などの詳細ルールはSTO内部の運用に格納し、現場には出さない。

## 5. 90日の約束を3行にする

- **30日**：営業と財務の数字がつながる
- **60日**：顧客・案件のランクが決まる
- **90日**：力の入れ直しを実行し、営業利益＋5億円（予算比）に向かう
