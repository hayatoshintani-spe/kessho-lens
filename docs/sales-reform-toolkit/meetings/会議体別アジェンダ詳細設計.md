# 会議体別アジェンダ詳細設計

**作成：新谷隼人（専務執行役員）／運用：STO（社外秘・取扱注意）**
**位置づけ：`会議運用設計書.md`（会議体系・ルール）の下位文書として、各会議体のアジェンダを分単位・論点の型・フェーズ別変化まで詳細化する。矛盾時は本書が最新**

---

## 0. 全会議共通の設計思想

1. **アジェンダは「共有／議論／決定」を項目ごとに明示する。** 全部「共有」になった会議は赤信号（坪井さんが週次レビューで検知・報告）
2. **冒頭に「今日決めること」、末尾に「宿題の読み上げ」。** この2つがない会議は開かない
3. **フェーズでアジェンダは変わる。** 90日を3フェーズに分け、各会議の標準アジェンダを切り替える
   - **Phase 1（Day 0〜30）データ整備期**：棚卸し・要確認キュー・データ充填が議題の中心
   - **Phase 2（Day 30〜60）評価・設計期**：スコアリング・ランク確定・ルール設計が中心
   - **Phase 3（Day 60〜90）実行移行期**：資源再配分の実行・KPI/KAIのPDCAが中心
4. **時間は延長しない。** 議論が割れたら「論点として上位会議へ」か「宿題化して次回」の二択で切る（議長の専権）
5. **資料は作り込まない。** 分科会・戦略会議はWordベース、点検会議のみキーチャート5枚（作成上限2時間）

## 1. 接点づくり分科会（週次75分／議長：黒澤さん）

### 目的
消費者・ファンとの日常接点を設計し、「待ちの許諾窓口」から「接点を作りに行く営業」への転換の実弾（EC・イベント・SNS・ファン施策）を作る。

### 標準アジェンダ（75分）

| 時間 | 項目 | 種別 | 中身 |
|---|---|---|---|
| 0:00-0:05 | ① 前回宿題の消し込み | 確認 | 宿題管理シートを画面共有し、完了／停滞を機械的に確認。停滞は理由と新期限をその場で |
| 0:05-0:15 | ② ファン・顧客データの定点 | 共有 | 接点KPIの定点観測（SNSフォロワー・EC会員・イベント動員・D2C売上等）。数字はSTOが事前転記、ここでは変化の理由だけ議論 |
| 0:15-0:40 | ③ 本日の論点（1〜2件） | **議論** | 1論点20分まで。「問い→現状→選択肢→決め」の順で議長が仕切る（論点の型は下記） |
| 0:40-0:60 | ④ 施策のPDCA | 議論 | 走っている施策の結果と次の一手。「やってみてどうだったか」を数字で。結果が出ていない施策は継続/修正/中止を明示的に選ぶ |
| 0:60-0:70 | ⑤ 決定と戦略会議への上申 | **決定** | 今日決めたことの確認。自分たちで決め切れなかった論点は「戦略会議に上げる論点」として文言まで確定 |
| 0:70-0:75 | ⑥ 宿題の読み上げ | 確認 | 誰が・何を・いつまでに。坪井さんがその場で宿題管理シートに起票 |

### この分科会の論点の型（③で扱う問いの例）
- Phase 1：ファン接点の現状棚卸し——今どこに・誰と・どんな接点があるか／接点データはどこに散在しているか
- Phase 2：どの顧客セグメント（ランク）にどの接点施策を当てるか／CRM・D2C価値スコアの判定に使う接点データの定義
- Phase 3：施策の投資対効果と拡大・撤退判断／接点データの営業（ライセンス分科会）への引き渡し方

### 議長（黒澤さん）の心得
- 施策アイデアの発散は歓迎だが、**必ず「誰に・何を・いつ試すか」まで収束させてから閉じる**
- ライセンス営業に絡む論点（例：ライセンシー共同キャンペーン）は抱えず、ライセンス分科会と共同論点にしてPMO経由で調整

## 2. ライセンス営業改革分科会（週次75分／議長：南谷さん）

### 目的
棚卸し・スコアリング・ランクを運用に乗せ、案件パイプラインを回し、「どの顧客・案件に力を注ぐか」の実務判断を行う。**改革の本丸であり、棚卸しマスターと直結する唯一の分科会**。

### 標準アジェンダ（75分）

| 時間 | 項目 | 種別 | 中身 |
|---|---|---|---|
| 0:00-0:05 | ① 前回宿題の消し込み | 確認 | 同上 |
| 0:05-0:20 | ② パイプライン定点 | 共有 | 棚卸しマスターから STO が抽出した定点4点：(a) 案件ステージ別件数と金額 (b) 停滞案件（30日以上動きなし）(c) 新規流入 (d) 今月の成約・失注。**数字の読み上げはしない**。異常値と停滞だけ議論 |
| 0:20-0:45 | ③ 本日の論点（1〜2件） | **議論** | 1論点20分まで（論点の型は下記） |
| 0:45-0:60 | ④ 停滞案件・支援要請 | 議論 | 停滞理由が「担当で解けない」案件の支援判断：部長間調整／トップ外交投入／保留の明示。**トップ外交候補はここで発議**し、戦略会議で確定 |
| 0:60-0:70 | ⑤ 決定と戦略会議への上申 | **決定** | 同上。特にランク基準・撤退基準に触れる論点は必ず上申（分科会で決め切らない） |
| 0:70-0:75 | ⑥ 宿題の読み上げ | 確認 | 同上 |

### この分科会の論点の型
- Phase 1：棚卸しの完成度——要確認キューの解消状況／部長確認会の結果の反映／NX外案件（海外・イベント・広告）の捕捉方法
- Phase 2：スコアリング運用——5軸採点の実施と部長間の目線合わせ／SABCランクの初回確定／ランク別の標準対応（Sに何をする・Cをどう省力化する）の設計
- Phase 3：資源再配分の実行——ランク別対応の実行状況／撤退・縮小候補の交渉状況／新規開拓とアップセルのパイプライン化

### 議長（南谷さん）の心得
- **個別案件の深掘りに吸い込まれない。** 1案件5分超えたら「担当と部長で個別に」と切り、会議は構造の議論に戻す
- ランク・撤退の話は感情が乗りやすい。「基準の議論」と「特定顧客の議論」を意識的に分離する（基準は上申、個別はデータで）
- ②の定点はSTO（坪井さん）がマスターから自動抽出。**会議用に別資料を作らせない**

## 3. 経営基盤強化分科会（週次75分／議長：高橋さん）

### 目的
改革を支える「仕組み」を作る——KGI/KPI/KAI体系、管理ルール・ガイドライン、RACI、工数計測、AI活用。他2分科会が走るための道路を敷く。

### 標準アジェンダ（75分）

| 時間 | 項目 | 種別 | 中身 |
|---|---|---|---|
| 0:00-0:05 | ① 前回宿題の消し込み | 確認 | 同上 |
| 0:05-0:15 | ② 仕組みの稼働状況 | 共有 | 作った仕組みが使われているかの定点：工数申告の提出率／棚卸しマスターの更新状況／決定ログの消し込み率。**「作ったのに使われていない」を最重要アラートとして扱う** |
| 0:15-0:40 | ③ 本日の論点（1〜2件） | **議論** | 1論点20分まで（論点の型は下記） |
| 0:40-0:55 | ④ ルール・ガイドラインのレビュー | 議論 | 起草中のルール（ランク基準・撤退基準・監修ガイドライン等）の条文レビュー。他分科会からの改訂要望の裁き |
| 0:55-0:70 | ⑤ 決定と戦略会議への上申 | **決定** | ルールの「制定・改定」は必ず戦略会議→（重要なものは）点検会議へ上申。分科会は起草と推奨案まで |
| 0:70-0:75 | ⑥ 宿題の読み上げ | 確認 | 同上 |

### この分科会の論点の型
- Phase 1：計測の立ち上げ——工数申告の定着（評価に使わない原則の周知含む）／KGI→KPI→KAIの逆算設計／粗利算定2層方式の実装（財務・柳沼さんラインと接続）
- Phase 2：ルールの制定——SABCランク基準の成文化／撤退・縮小の判断基準と手続き／監修リードタイムの計測方法（NX外の監修往復をどう記録するか）
- Phase 3：定着と自動化——ルールの運用点検／ダッシュボード化／ガイドラインのAI組み込み（AI戦略とアライン）／90日後の恒常運営への引き継ぎ設計

### 議長（高橋さん）の心得
- **仕組みは「使う人」がいて初めて完成。** 制度設計の美しさより提出率・更新率を優先する
- 評価制度に踏み込む論点（宍戸さんの指摘等）は分科会で答えを出さない。「論点整理＋選択肢」まで作って戦略会議へ

## 4. 戦略会議（隔週90分／議長：永竹社長）

### 目的
①15週マイルストーンに対するon-trackチェック ②リソース配分・部門横断の**決め切り** ③点検会議（会長）に上げる論点の選別と推奨案のすり合わせ。**自分たちで決められることはここで全部決める**。

### 標準アジェンダ（90分）

| 時間 | 項目 | 種別 | 中身 |
|---|---|---|---|
| 0:00-0:05 | ① 本日決めるべき事項の確認 | 確認 | 「今日決めること」最大4件を冒頭提示（STOが前日までに確定、新谷が前日30分で事前確認済み） |
| 0:05-0:10 | ② 前回決定事項の消し込み | 確認 | 決定ログの進捗。遅延は理由と対策を1分以内で |
| 0:10-0:25 | ③ 全体進捗（15週計画） | 共有 | 3分科会×マイルストーンの信号（緑/黄/赤）。**緑は飛ばす**。黄・赤のみ理由と回復策を議論 |
| 0:25-0:70 | ④ 意思決定論点（本丸） | **決定** | 1論点10〜15分×3〜4件。分科会リーダーが「問い→選択肢→推奨案」を口頭＋Word1枚で提示し、社長が決める。決め切れないもののみ「点検会議行き」の判定 |
| 0:70-0:80 | ⑤ リソース・部門横断の調整 | **決定** | 人の応援・優先順位の衝突・部門間の滞留を裁く。トップ外交の投入先（誰が・どこへ・何を握りに）もここで確定 |
| 0:80-0:87 | ⑥ 点検会議への論点整理 | 決定 | 会長に上げる論点（最大3件）と推奨案の方向を確定。「会長にどう見せるか」の演出ではなく「何を決めてもらうか」の実質を確認 |
| 0:87-0:90 | ⑦ 宿題の読み上げ | 確認 | 同上 |

### ④意思決定論点の提示フォーマット（Word半枚・分科会リーダー起草）
```
論点：〔一文の問い。例：C ランク顧客の年次更新を自動化してよいか〕
背景：〔なぜ今決める必要があるか。3行以内〕
選択肢：A案／B案（各1行＋メリット・リスク1行ずつ）
推奨：〔A案。理由2行〕
決めてほしいこと：〔採否＋実施条件〕
```

### フェーズ別の④の中身
- Phase 1：棚卸しの完成宣言基準／データ供給ライン（財務・NX）の定例化／工数計測の開始判断
- Phase 2：ランク基準の承認／ランク別標準対応の承認／撤退・縮小候補リストの初回審議（個別交渉の着手判断）
- Phase 3：資源再配分の実行判断（担当替え・注力先変更）／90日後の恒常体制（STOの出口）／来期計画への織り込み

### 運用上の要点
- 戦略会議で出た結論は点検会議では**報告のみ**。同じ論点を二度議論しない
- 論点が5件を超えたらSTOが事前に仕分けて持ち越しを明示（詰め込みは全論点を浅くする）

## 5. 点検会議（月次60分／議長：会長）

※標準アジェンダ60分・キーチャート5枚型・論点選別基準・事前準備タイムラインは `会議運用設計書.md` 3章の通り（重複定義しない）。本書では**運用の詳細**のみ追加する。

### 論点1枚（キーチャート4枚目）の書き方詳細
- **1論点1枚厳守**。問い（1行）→選択肢の比較表（2〜3案×評価軸2〜3個）→推奨と理由（2行）→「本日決めていただきたいこと」（1行）→決定記入欄（空欄で持参し、その場で書き込む）
- 選択肢は必ず**推奨案を含む2案以上**。1案だけの「承認取り」は論点ではなく報告に分類し直す
- 数字は根拠ページを付けない。問われたら口頭で答えられる準備をSTOと分科会リーダーがしておく（バックアップ資料の作り込み禁止）

### フェーズ別の「⑤意思決定」の中身
- Phase 1：改革の基本方針の追認／データ基盤投資の承認／トップ外交の初回ターゲット承認（会長自身の登板案件を含む）
- Phase 2：ランク基準・撤退基準の最終承認／聖域の扱い（会長案件・歴史的経緯のある取引先の評価ルール）——**ここは会長にしか決められない論点として正面から上げる**
- Phase 3：Plan点検からCheck/Action点検への切り替え（実行状況・KPI/KAI確認へ）／恒常体制への移行承認

### 会長への出し方の原則
- 事前送付は前日。**1ページ目が「本日決めること」**になっている構成
- 決定はその場で復唱し、キーチャートの決定欄に記入→24時間以内に決定ログへ転記・全関係者展開（STO）
- 「持ち帰って検討」が出たら、期限と再上程日をその場で確定してから閉じる

## 8. 会議体間の論点の流れ（詳細版）

```
【発生】分科会③④で議論 → 決め切れるものは⑤で決定（決定ログへ）
   │
   ├─ 決め切れない（リソース・部門横断・基準の制定）
   ▼
【仕分け】STO日次③で戦略会議アジェンダへ → リーダーがWord半枚の論点フォーマット起草
   │        → 新谷が前日30分で「問いの質」を確認
   ▼
【決め切り】戦略会議④⑤で社長が決定（決定ログへ）
   │
   ├─ 会長マターのみ（方針・投資・聖域・重大遅延：選別基準6項目）
   ▼
【上程】点検会議⑤で会長が決定 → 24時間以内に決定ログ転記・全関係者展開
   ▼
【還流】次回の各会議①「前回宿題・決定の消し込み」で実行を確認
```

**逆流の禁止**：下位会議で決めたことを上位会議で蒸し返さない。上位会議は「決定の変更」ではなく「新しい事実に基づく再決定」としてのみ扱う（再決定は理由を決定ログに残す）。

| タイミング | 誰が | 何を |
|---|---|---|
| フェーズ移行の判断 | 戦略会議 | 移行条件の充足を確認して宣言（Phase1→2：棚卸し完成＋財務列充填／Phase2→3：ランク初回確定＋ランク別対応の承認） |
| アジェンダの切り替え | 坪井さん | 宣言の翌週から、各会議の③（論点）と定点の中身を本書のフェーズ別の型に差し替え |

## 10. よくある失敗と議長・STOの対処

| 症状 | 検知 | 対処 |
