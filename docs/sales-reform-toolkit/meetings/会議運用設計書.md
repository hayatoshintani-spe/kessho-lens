# 構造改革 会議運用設計書
## 分科会 × 戦略会議 × 点検会議 × PMO会議 の運用ルール

**作成：新谷（専務執行役員）／運用：PMOチーム**
**前提：カーニー支援下の構造改革会議サイクル（分科会×2 → 戦略会議 → 点検会議、PMO日次）に基づく。本書は円谷側の運用ルールを定めるもの**

---

## 1. 会議体系の全体像

```
【日次】PMO会議（30分）────── 進捗・アラート・各会議のアジェンダ仕込み
【週次】分科会 ×3 ──────────── What（何をやるか）の策定と How（実行）のPDCA
   ├─ 接点づくり分科会
   ├─ ライセンス営業改革分科会
   └─ 経営基盤強化分科会
【隔週】戦略会議 ─────────────  15週マイルストーンの点検・リソース配分・戦略的意思決定（社長）
【隔週】点検会議 ─────────────  会長による進捗の点検と重要テーマの意思決定
```

**基本サイクル：分科会×2回 → 戦略会議 → 点検会議**（2週間で1周）

**週間リズムの例**（曜日は初回に確定）
| 曜日 | 会議 |
|---|---|
| 毎営業日 朝 | PMO会議（30分） |
| 火 | 分科会（3本を並行または連続で設定） |
| 木（隔週） | 戦略会議 |
| 金（隔週・戦略会議の翌週） | 点検会議 |

## 2. 会議体の定義（一覧）

| | 分科会 | 戦略会議 | 点検会議 | PMO会議 |

| **目的** | 各テーマのWhat策定とHowのPDCA | 15週マイルストーンの進捗点検・リソース配分・戦略的意思決定 | 会長自らが構造改革を点検し、重要テーマを意思決定 | 進捗共有・アラート・会議アジェンダの仕込み |
| **頻度・時間** | 週次・60〜90分 | 隔週・60〜90分 | 隔週・60分 | 日次・30分 |
| **議長** | 分科会リーダー（黒澤さん・南谷さん・高橋さん） | 永竹社長 | 会長 | PMOリード |
| **出席** | リーダー＋関連部長＋チームメンバー＋PMO | 社長＋分科会リーダー＋メンバー＋PMO | 会長＋社長＋分科会リーダー＋PMO | PMOチームのみ |
| **議論の粒度** | 実務レベル（What/Howの中身） | マネジメントレベル（スケジュール・配分・部門横断） | 経営判断レベル（方針・優先順位・投資・体制） | 運営レベル |

## 3. 点検会議の運用（詳細）

### 3.1 定義
> 点検会議とは、分科会・戦略会議で整理された検討結果と実行状況を、会長・経営陣が確認し、重要テーマの意思決定・優先順位付け・課題対応方針の決定を行うことで、構造改革のPDCAを前に進める会議である。

進捗報告会ではない。**「何を決めたか」が残らない点検会議は失敗**とみなす。

### 3.2 標準アジェンダ（60分）
| 時間 | 項目 | 中身 |
|---|---|---|
| 0:00-0:05 | ① 本日決めるべき事項の確認 | 冒頭に「今日決めること」を最大3件提示 |
| 0:05-0:10 | ② 前回決定事項の進捗確認 | 決定ログの消し込み（決定・担当・期限・進捗・遅延理由） |
| 0:10-0:20 | ③ 全体進捗 | 15週計画に対する3分科会の信号（緑/黄/赤）・遅延テーマ・リスク |
| 0:20-0:30 | ④ 分科会別ハイライト | 各分科会「決まったこと／次にやること／課題」を1枚ずつ |
| 0:30-0:50 | ⑤ 意思決定（本丸） | 論点ごとに選択肢・推奨案を提示し、会長が決定。決定・理由・担当・期限をその場で記録 |
| 0:50-0:57 | ⑥ 課題・ボトルネックの対応方針 | 進まない理由と対応（誰が・いつまでに・どう） |
| 0:57-1:00 | ⑦ 次回までのToDo確認 | ToDo・担当・期限・成果物の読み上げ |

※ 改革後半（実行フェーズ）は⑤の比重を下げ、「実行状況・KPI/KAIの確認」「結果の振り返り」を⑤の位置に入れる（Plan側の点検→Check/Action側の点検へ移行）。

### 3.3 資料ルール（キーチャート5枚型）
点検会議はWordベースを基本としつつ、以下の**5枚だけPPT**で用意する（テンプレート：`点検会議_キーチャートテンプレート.pptx`）。

1. **本日決めること**（最大3件：論点・背景・選択肢・推奨）
2. **全体進捗**（15週計画×3分科会の信号表示・遅延・リスク）
3. **分科会別ハイライト**（決まったこと／次にやること／課題）
4. **意思決定論点**（1論点1枚：選択肢比較・推奨と理由・決定欄）
5. **次回までのToDo**（担当・期限・成果物＋前回決定の消し込み）

作成はPMO。作成時間の上限は**1回あたり2時間**（作り込み始めたら本末転倒）。

### 3.4 論点の選別基準（何を点検会議に上げるか）
以下のいずれかに該当する論点のみ、戦略会議経由で点検会議へ上げる。

1. **方針・優先順位**：改革の方向性・重点ターゲット・リソースの大きな傾斜配分に関わる
2. **投資・費用**：新たな支出・システム投資・体制増強を伴う
3. **部門横断・権限**：複数部門の利害調整、権限・組織・RACIの変更を要する
4. **対外・トップ関与**：会長・社長のトップ面談、重要パートナーとの交渉方針
5. **ルール制定**：ランク基準・撤退基準・管理ルール・ガイドラインの制定/改定
6. **重大な遅延・リスク**：15週計画に対して赤信号のテーマ

該当しないものは戦略会議・分科会で決め切る（**上げすぎは点検会議の質を下げる**。1回3論点以内が目安）。

### 3.5 事前準備のタイムライン
| タイミング | 誰が | 何を |
|---|---|---|
| 開催3営業日前 | PMO会議 | 分科会・戦略会議から上がった論点を仕分け、アジェンダ案を確定 |
| 2営業日前 | PMO | キーチャート5枚を作成、分科会リーダーが内容確認 |
| 前日 | PMO | 会長・社長へ事前送付（「本日決めること」が最初に目に入る構成で） |
| 当日 | PMO | 決定ログをその場で記録し、24時間以内に全関係者へ展開 |

## 4. 戦略会議の運用

- **役割**：①15週マイルストーンにon-trackかのチェック　②リソース配分・部門横断の戦略的意思決定　③点検会議に上げる論点の選別と「会長向けに出す方針」のすり合わせ
- **標準アジェンダ**：前回の振り返りとスケジュール／各チームの進捗（スケジュール管理レベル。詳細は分科会でやる）／議論・意思決定事項／まとめ（次回までのTODO・会長向け方針）
- **点検会議との違い**（運用上の要点）
  - 戦略会議＝**決め切る場**（自分たちで決められることはここで決める）
  - 点検会議＝**会長の判断が必要なものだけ**を、選択肢と推奨案の形にして上げる場
  - 同じ論点を二度議論しない。戦略会議で出た結論は点検会議では「報告＋確認」のみ
- **資料**：Wordベース（`戦略会議_アジェンダ議事テンプレート.docx`）

## 5. 分科会の運用（3分科会共通）

- **役割**：What（何をやるか）の策定と、How（実行）のPDCA
- **3分科会とスコープ**
  | 分科会 | リーダー（想定） | 主なスコープ |
  |---|---|---|
  | 接点づくり | 黒澤さん | 消費者・ファン理解／日常接点設計／EC・イベント・SNS／ファン化施策 |
  | ライセンス営業改革 | 南谷さん | 既存ライセンシー分析・SABCランク／新規開拓／営業資料・トーク高度化／アップセル・クロスセル／営業管理体制 |
  | 経営基盤強化 | 高橋さん | 会議体設計／KGI・KPI・KAI設計／RACI／管理ルール・ガイドライン／AI活用 |
- **標準アジェンダ**（例：ライセンス営業改革）：前回の振り返りとスケジュール／各検討チームの進捗（進捗により濃淡）／チームごとの「共有→議論→次回までの検討事項」／まとめ
- **運用原則**
  - 資料の作り込み無し（Wordベース：`分科会_アジェンダ議事テンプレート.docx`）
  - 「共有」「議論」「決定」をアジェンダ上で明示的に区別する（全部「共有」になったら赤信号）
  - 戦略会議に上げる論点は会議の最後に確定し、PMOへ渡す
- **営業改革ツールとの接続**：ライセンス営業改革分科会は、既存の営業改革ツールキット（案件・顧客リスト、SABCランク、時間記録、決定ログ）をそのまま検討・運用のベースに使う。二重管理を作らない

## 6. PMO会議の運用（日次30分）

- **参加**：PMOチームのみ（営業改革側の推進チーム＝STO機能はPMOに統合。呼称はPMOに一本化）
- **標準メニュー**（30分固定）
  1. 各チームの進捗・アラート共有（10分）
  2. 協働ポイント・詰まりの調整（10分）
  3. 戦略会議・点検会議のアジェンダ仕込み（テーマの出し分け・濃淡調整）（10分）
- **資料不要**。Word/共通Excel（決定ログ・ToDoリスト・アラートリスト）に直接書き込む
- **アラート基準**：期限超過／2回連続で進捗なし／部門間で滞留──のいずれかは自動的に翌回の戦略会議アジェンダ候補へ

## 7. 決定ログとToDo管理（全会議共通）

- **1つの決定ログに全会議の決定を集約**（既存の `03_KPI・会議運営・90日WBS.xlsx`「決定ログ」シートを共通台帳として使用。将来はNotion/共通Excelへ）
- 記録項目：決定ID／会議日／会議体／対象／決定内容／理由／担当／期限／状態／完了確認日
- **運用ルール**
  1. 「検討する」は決定ではない（誰が・いつまでに・何を、まで書けて決定）
  2. 各会議の冒頭で前回決定の消し込みを行う
  3. 期限超過が2回続いた項目は、上位会議（分科会→戦略会議→点検会議）へ自動エスカレーション
- **管理責任**：PMO（記録・展開・消し込み管理）

## 8. KGI・KPI・KAIの段階導入

| フェーズ | 内容 |
|---|---|
| 前半（What策定期） | 会議は「検討の進捗」を管理（マイルストーン・信号）。指標は設計段階：KGI（例：ライセンス収入・営業利益）→KPI（例：重点ライセンシー面談数・新規商談数・成約率・監修所要日数）→KAI（例：提案書作成数・アプローチ数・DB入力率）の体系をKGIから逆算して設計 |
| 後半（How実行期） | 打ち手のPDCAをKPI/KAIで管理。点検会議アジェンダ⑤を「実行状況・KPI/KAI確認」に切り替え。管理フォーマットは既存KPIシートを拡張（PMOが月次更新） |
| 長期調整項目 | ライセンシーランク等、半期・年次で見直すものは管理ルール・ガイドラインとして文書化。ガイドラインのAI組み込み（半自動化）はAI戦略側とアラインの上で経営基盤強化分科会が所管 |

## 9. 既存「営業改革」会議設計との整合（重要）

営業改革グランドデザインで設計した会議体は、本サイクルに以下の通り**統合**する（並立させない）。

| 営業改革側の設計 | 統合先 |
|---|---|
| 週次パイプライン会議（週次・領域別） | **ライセンス営業改革分科会**（週次）に統合。案件・停滞・支援要請のアジェンダをそのまま持ち込む |
| 月次ポートフォリオ会議（経営出席・撤退/経営支援判断） | **戦略会議＋点検会議**に分割統合。リソース配分・省力化判断は戦略会議、撤退・投資・トップ関与は点検会議へ |
| STO（推進チーム） | **PMOチーム**に統合（機能・ツールは継承） |
| 決定ログ・案件マスタ・時間記録・KPIシート | そのまま共通ツールとして全会議で使用 |
