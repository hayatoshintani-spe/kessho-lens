# 営業改革 運用指南書 — 現場で回すための実務マニュアル

**作成：新谷隼人（専務執行役員）／営業改革推進室（STO）（社外秘・取扱注意）**
**位置づけ：設計書群（STO設計書・会議運用設計書・会議体別アジェンダ詳細設計・工数活用設計）を「今日なにをするか」に落とした実務マニュアル。設計の理由や背景は各設計書へ、手の動かし方は本書へ**

---

## 0. この指南書の使い方

自分の役割の章だけ読めば動けるように書いてある。全部読む必要はない。

| あなたは | 読む章 |
|---|---|
| 坪井さん（STOリード） | 1章＋5章＋6章 |
| 岡田さん（PMO・会議運営） | 2章＋5章＋6章 |
| 新谷（オーナー） | 3章＋6章 |
| 部長 | 4章＋6章のうち自分に関わる場面 |
| 分科会リーダー（黒澤さん・南谷さん・高橋さん） | 4章の後半＋会議体別アジェンダ詳細設計の自分の分科会の節 |

**大原則（全員共通・3つだけ）**
1. 工数データは資源配分の設計のためのもの。**個人の評価には一切使わない**
2. 宿題は「誰が・何を・いつまでに」の3点セット。主語が組織名の宿題は存在しない
3. 24時間で解けないものは抱えずに上げる。**上げるのは失点ではない。滞留が失点**

## 1. 坪井さん（STOリード）の運用

### 1-1. 週次ルーティン

| 曜日 | やること | 使う資料 |
|---|---|---|
| 月 | マスターの週次更新：先週分の反映・要確認キューの処理（自分で判断できるものは即断、部長判断が要るものは領域別リストへ）。処理後に「再加工日時」を更新 | 棚卸しマスター（共有版） |
| 火 | 分科会用データパックの供給：パイプライン定点4点（ステージ別件数と金額／停滞30日超／新規流入／成約・失注）をマスターから抽出してライセンス分科会へ。**会議用に別資料は作らない**（シートの該当ビューを見せるだけ） | 同上 |
| 水 | データ処理集中日：財務データの流し込み・名寄せ・スコア集計。割り込みはこの日に寄せない | 同上＋財務データ |
| 木 | （隔週）戦略会議に出す数字の最終確認 | KPIシート |
| 金 | 17:00週次レビューで運転計器を報告（キュー残・データ鮮度・宿題は岡田さん分と合わせて） | STO週次運用管理.xlsx |

### 1-2. データ処理の標準手順

**要確認キューの処理（月曜）**
1. 003_要確認キューを開き、処理パターンでソート
2. 「担当候補一意」→ 候補をそのまま確定。迷ったら確定せずコメントを付けて部長行きへ
3. 「担当候補なし」「組織名」→ 営業領域別に分割し、部長確認用の一覧に転記
4. 処理した行は理由コードを残したままステータスだけ変える（**行を消さない**。後から監査できるように）

**財務データが届いたら（都度）**
1. 受領ファイルをそのまま保存（原本は加工しない。加工はコピーで）
2. 顧客名寄せキーで746社と突合 → マッチしない先はキューへ（新規の表記ゆれとして）
3. 年間取引額・年間粗利・直近取引年を一括転記
4. 直近取引年が入ったら05_休眠顧客を自動抽出
5. 反映結果（マッチ率・未マッチ件数）を金曜レビューで報告

**スコアリング運用（財務列充填後に開始）**
1. 「取引実績」列は金額閾値から自動判定（採点定義シートの基準）
2. 他4軸は部長・分科会の判断待ち。**自分で採点しない**。空欄のまま確認会へ出す
3. 採点が入ったらS/A/B/C自動判定を確認し、分布（S:A:B:C比率）を分科会へ報告

### 1-3. やらないこと
会議の日程調整・議事録・督促（岡田さんの領域）。頼まれても引き受けず岡田さんへ回す。

## 2. 岡田さん（PMO・会議運営）の運用

### 2-1. 毎朝10分のチェック（始業後すぐ）

1. STO週次運用管理.xlsxの宿題管理シートを開く
2. 停滞日数の色を見る：**黄（3日）→ 担当本人にチャットで一言督促**（部長経由にしない・詰問しない。「進みそうですか？詰まってたら言ってください」）
3. **赤（5日）→ 新谷へエスカレーション**（型：①何が止まっている ②誰の判断が要る ③放置すると何が遅れる）
4. 今日の会議の資料・論点が揃っているか確認。揃っていなければ起草者に朝のうちに連絡

### 2-2. 会議前後の標準動作

**前日まで**：アジェンダ確定・配布（分科会=Word1枚、戦略会議=論点フォーマット、点検会議=キーチャート5枚※作成上限2時間）。戦略会議の前日は新谷の30分事前確認を必ず取る
**当日**：議事は「共有/議論/決定」のタグ付きでメモ。宿題はその場で宿題管理シートに起票（会議終了時に読み上げ）
**24時間以内**：決定事項を決定ログ（03_KPI・会議運営・90日WBS.xlsx）へ転記し、関係者へ展開

### 2-3. 週次ルーティン

| 曜日 | やること |
|---|---|
| 月 | 今週の会議体スケジュール確定、アジェンダドラフト配布、部長確認一覧の配布（坪井さんから受領） |
| 火 | 分科会×3の陪席・議事録・宿題起票 |
| 水 | 宿題の中間督促、翌週の日程調整 |
| 木 | （隔週）戦略会議の運営 |
| 金 | 週次レビューの進行（アジェンダは毎回同じ5点）、議事録タグの週次集計（「全部共有」の会議がないか） |

### 2-4. 差し戻しの基準（迷わず機械的に）
- 宿題の主語が組織名 → 個人名に直させてから起票
- 会議資料がWord1枚超・点検会議以外のPPT → 差し戻し
- 「検討する」で終わる決定 → 決定ログに載せず、未決として翌回アジェンダ冒頭へ

## 3. 新谷（オーナー）の運用

### 3-1. 週の固定枠（この4つだけはカレンダーから動かさない)

1. **金17:00-17:30 週次レビュー**：エスカレーションを裁く（その場で決めるか、誰に当てるか決める。持ち帰らない）
2. **戦略会議の前日30分**：アジェンダ事前確認。見るのは「問いの質」だけ——この論点は選択肢と推奨案の形になっているか、社長が決められる形か
3. **点検会議の前日**：キーチャート5枚に目を通す。1ページ目が「本日決めること」になっているか
4. **トップ外交の実施後48時間以内**：面談メモを登録（トップ外交48時間登録メモ.md の様式）

### 3-2. 登板ポイント（自分が前に出る場面）
- 専任化・応援などの人の調整（部長への直接依頼）
- Day 30の4象限閾値の承認、Day 60の見直し本丸（撤退・条件改定）の審議——**部長に嫌われ役を押し付けない**
- 未記入部門・温度の低い部長との個別対話（事務局経由にしない）

### 3-3. やらないこと
進捗の細かい追いかけ（岡田さんの領域）。会議で細部の議論に入りそうになったら「それは分科会で」と自分で切る。

## 4. 部長・分科会リーダーの運用

### 4-1. 部長の週次（合計1〜2時間想定）

1. **自領域の棚卸しシートの事実確認**：担当・関係状態・案件ステータスが実態と合っているか。違っていたら直接修正かキューへ（週30分）
2. **L1の後押し**：担当者の「時間の使い方の変更」は承認不要と伝える。事後報告でよい
3. **L2の判断**：担当替え・部門内省力化は自分で決めて動かす（分科会への報告のみ）。**戦略会議を待たない**
4. **工数申告の見届け**：自部門の提出率が下がったら本人に一言（内容には踏み込まない。出しているかだけ）

### 4-2. 確認会（初回・2〜3時間）での部長の役割
①冒頭15分：担当未確定リストの確定 ②自領域の顧客関係・案件ステータスの事実確認 ③パートナー候補・トップ外交先の口頭ヒアリングに答える（記入は事務局）。**評価や採点はしない。事実だけ**

### 4-3. 分科会リーダーの会議運営（75分の仕切り）
- 冒頭5分の宿題消し込みと最後5分の宿題読み上げは省略しない（ここを省くと2週で会議が崩れる）
- 論点は1回2件まで・1件20分で切る。個別案件は5分で「担当と部長で個別に」
- 戦略会議へ上げる論点は会議の最後に**文言まで**確定（論点フォーマット半枚は自分で起草。STOに書かせない——論点の当事者はリーダー自身）
- 全部「共有」で終わった回は、次回の論点を閉会前にその場で決めてから解散

## 6. 場面別の手順（こうなったら、こうする）

| 場面 | 手順 |
|---|---|
| **新しい案件・顧客が発生した** | 担当が棚卸しマスターに1行起票（案件名・顧客・ステージ・金額見込）→ 坪井さんが月曜の週次更新で名寄せ・整合チェック。起票漏れは部長の週次事実確認で拾う |
| **財務データが届いた** | 坪井さんが1-2の手順で流し込み。未マッチはキューへ。反映率を金曜報告 |
| **宿題が停滞した** | 3日=岡田さんが本人へ督促 → 5日=新谷へエスカレーション → 期限超過2回=上位会議のアジェンダへ自動上程 |
| **会議で決まらなかった** | 「宿題化して次回」か「論点として上位会議へ」の二択を議長がその場で選ぶ。持ち越しの放置は禁止（未決のまま消えるのが最悪） |
| **ルールを変えたい（ランク基準・採点定義など）** | 分科会で起草→戦略会議で承認（重要なものは点検会議）。**運用しながら勝手に変えない**。変更したら岡田さんがテンプレート・シートに反映し全体通知 |
| **現場から「工数が評価に使われるのでは」と不安の声** | その場で否定し、全社説明会資料の該当ページを示す。繰り返し出るようなら週次レビューで新谷へ（新谷が次の全体の場で再度明言する） |
| **要確認キューに新種の判断が出てきた** | 坪井さんが独断せず「処理パターン」を1つ追加してキューへ。パターンの追加は金曜レビューで共有 |
| **部長から「この顧客は特別だ」と例外要求が出た** | 例外は認める前提で、**理由の明文化**（CRM価値・ブランド価値・歴史的経緯のどれか）とセットでのみ受ける。明文化された例外はリスト化して点検会議の視界に入れる |
| **STOに実行業務（顧客対応等）の依頼が来た** | 岡田さんが「STOのスコープ外」として部長へ差し戻す（STO設計書2章を示す）。断りにくければ新谷へ |
| **メンバーが途中から参加した** | 全社説明会資料＋本書の該当章＋自分の役割のシートだけ渡す（全資料を渡さない。迷子になる） |

## 7. 週次レビュー・チェックリスト（金曜17:00、これだけ見れば締まる）

- [ ] 要確認キュー残：先週比で減っているか
- [ ] マスター再加工日時：今週の日付か
- [ ] 財務データ：予定どおり受領したか（遅延なら催促の担当を決める）
- [ ] 宿題消化率80%以上か／停滞5日超はゼロか
- [ ] 今週の会議で「全部共有」の回はなかったか
- [ ] 来週の戦略会議/点検会議の論点は「決められる形」になっているか
- [ ] エスカレーションは全件その場で裁いたか（持ち帰りゼロ）
- [ ] 専任2名の負荷は限界に近づいていないか／増員トリガー3条件に接近していないか
