# STO設計書 — 営業改革推進室（Sales Transformation Office）体制と運用

**作成：新谷隼人（専務執行役員）／営業改革事務局（社外秘・取扱注意）**
**位置づけ：営業改革グランドデザインの実行機関であるSTOの、体制・権限・運用のすべてを定める文書。運用資料は本書末尾の付属資料一覧を参照**

---

## 1. STOのグランドデザイン

### 1-1. ミッション

STOは営業改革を**実行する部隊ではない**。実行するのは各部長と分科会である。STOの存在理由は次の3機能に限定する。

1. **データを回す** — 棚卸し・スコアリング・KPIの数字を、正しく・速く・止めずに供給する
2. **会議を回す** — 分科会×3・戦略会議・点検会議のサイクルを設計どおりに運転し、宿題を消化させる
3. **意思決定に上げる** — 現場で解けない詰まりを24時間以内にオーナーへ届け、役職の力で外す

### 1-2. 設計原則

- **最小人員で始める。** 専任2名＋兼務2名の計4名。機能が先、人数は後。増員は本書9章のトリガー条件でのみ行う
- **STOは実行に手を出さない。** STOが案件対応を代行し始めると「事務局がやってくれる」構造になり、部長の当事者性が死ぬ。改革の主役は部長である
- **外部に依存しない。** 会議の型・論点設計は内製する。データ作業を外部に出すと社内にノウハウが残らない
- **工数把握は評価に使わない。** STOが集める工数データは資源配分の設計のためであり、個人評価には一切使用しない（グランドデザインの大原則をSTO運用でも堅持する）

### 1-3. 改革全体の中での位置

```
点検会議（会長）……………… 月次。改革が約束どおり進んでいるかの点検
    ↑ キーチャート5枚をSTOが作成
戦略会議（永竹社長）………… 隔週。分科会から上がる論点の意思決定
    ↑ アジェンダ・論点整理をSTOが準備（新谷が前日30分で事前確認）
分科会×3（黒澤・南谷・高橋）… 週次。接点づくり／ライセンス営業改革／経営基盤強化
    ↑ データ供給と宿題管理をSTOが担う
STO（本書）…………………… 日次。上記すべての運転席
```

## 2. スコープ — やること・やらないこと

| | やること | やらないこと |
|---|---|---|
| データ | 棚卸しマスターの管理、名寄せ、財務データの流し込み、スコアリング運用、KPI算出 | データの「評価・判断」（採点の判断は部長・分科会が行う） |
| 会議 | 日程・アジェンダ・議事録・宿題管理、会議体の運用改善 | 会議での意思決定（決めるのは各会議体の議長） |
| 実行 | 詰まりのエスカレーション | 案件の実行判断、顧客対応、交渉の代行 |
| 制度 | 論点の整理と選択肢の提示 | 評価制度・組織改編の決定（経営会議マター） |

## 3. 体制（4名）

| 役割 | 人 | 専任/兼務 | 責任範囲 |
|---|---|---|---|
| オーナー | 新谷（専務執行役員） | 兼務 | 意思決定・トップ外交・経営会議/点検会議への報告。STOの詰まりを役職で外す |
| STOリード | 坪井さん | **専任** | データ基盤の総責任者。棚卸しマスター・名寄せ・スコアリング運用・KPI算出。分科会へのデータ供給 |
| PMO・会議運営 | 岡田さん | **専任** | 会議体の設計運用（分科会×3・戦略・点検）、日程・アジェンダ・議事録・宿題管理、WBS進捗の日次追跡 |
| 財務リエゾン | 柳沼さん | 兼務（週2〜3時間） | 財務データの定期供給（取引先別売上・作品別配分率）、粗利算定ルールの検証 |

### 3-1. 各人の「やらないこと」

- **坪井さん**は会議調整をやらない。データに専念する
- **岡田さん**はデータ加工をやらない。宿題の督促と会議の質に専念する
- **新谷**は進捗管理をやらない。岡田さんのエスカレーションを受けて詰まりを外すことに専念する
- **柳沼さん**はSTOの定例に常時出席しない。データ受け渡しと算定ルール検証の必要時のみ

### 3-2. 専任化の条件（着任前に必ず実施）

坪井さん・岡田さんの専任化は、元部門の部長に**新谷から直接**次を伝える：「90日間は改革専任とする。期間中の評価は改革への貢献で新谷が責任を持つ。部門業務は引き継ぐか停止する（兼務での二重負荷は認めない）」。通知文面は付属資料②を使用。

### 3-3. 会議の型の内製（外部アドバイザーなしで回す設計）

- 会議の型は既に文書化済み（会議運用設計書・アジェンダテンプレート）。新規設計は発生しない
- 運用改善は岡田さんが金曜の週次レビューで回す
- **論点の質のチェックは新谷が戦略会議の前日に30分、アジェンダを事前確認して担保する**（新谷の定例工数として確保）
- 「論点が内輪の常識に寄る」リスクは、点検会議での会長の視点が外部の目の代替となる

## 4. 権限とエスカレーション

### 4-1. 決定権限の4段階

| レベル | 決められること | 決める人 |
|---|---|---|
| L1：STO内 | データ処理の手順、会議の日程・進行、テンプレートの改訂 | 坪井さん／岡田さん |
| L2：部長 | 自領域の担当割り、顧客・案件の事実確認、ヒアリング対応 | 各部長 |
| L3：オーナー | 領域をまたぐ調整、期限の変更、リソースの一時投入、対外的な依頼 | 新谷 |
| L4：会議体 | スコアリング基準の変更、撤退・縮小の判断、評価制度・組織に関わる事項 | 戦略会議／経営会議 |

### 4-2. エスカレーションルール

- **基準：自分のレベルで24時間以内に解けないものは、抱えずに1つ上へ上げる**
- 経路：坪井さん・岡田さん → 新谷（チャット即時＋エスカレーションログ記録）→ 必要に応じ戦略会議の論点へ
- 上げ方の型：「①何が詰まっているか ②誰の判断が要るか ③放置すると何がいつ遅れるか」の3点を1メッセージで
- エスカレーションは失点ではない。**滞留こそ失点**として運用する（宿題管理シートの停滞日数で機械的に検知）

## 5. 週次運用リズム（定常運転）

| 曜日 | STOの定常業務 |
|---|---|
| 月 | 岡田さん：今週の会議体スケジュール確定・アジェンダドラフト配布。坪井さん：マスターの週次更新（キュー処理・データ反映） |
| 火 | 分科会デー（3分科会を並行またはずらして開催）。岡田さん陪席・議事録・宿題起票。坪井さん：分科会用データパック供給 |
| 水 | 坪井さん：データ処理集中日（財務データ流し込み・名寄せ・スコア集計）。岡田さん：宿題の中間督促 |
| 木 | 隔週：戦略会議（前日=水曜夕方に新谷のアジェンダ事前確認30分）。月次：点検会議キーチャート作成週はここで仕上げ |
| 金 | **17:00 週次レビュー30分（新谷・坪井・岡田）**：①キュー残 ②データ鮮度 ③宿題消化率 ④来週の論点 ⑤エスカレーション確認 |

- 日次：岡田さんが宿題管理シートの停滞を朝10分でチェック（停滞3日で督促、5日で新谷へ自動エスカレーション）
- 月次：点検会議（会長）向けキーチャート5枚をSTOが作成（テンプレート既存）

## 6. データ運用ルール

### 6-1. マスターの管理

- 正本は棚卸し・スコアリングマスター1ファイルのみ。**コピーを配布しない**（閲覧は共有リンク、編集は坪井さんと明示的に許可した者のみ）
- 作業用シート（_tsby等）は、部長確認が完了した時点で正版シートへ昇格し、旧サンプル版は削除する
- 変更履歴：週次更新の完了時に「再加工日時」を必ず更新（既にconfig化済みの運用を継続）

### 6-2. データパイプライン（確立済みの3層構造を標準とする）

```
原文保持（00_転記） → 機械加工（002_加工用・名寄せキー付与） → 要確認キュー（003_人の判断待ち）
```

- 機械で判断できないものは推測せず要確認キューへ落とす（理由コード付き）
- キューの解消は「事務局で解けるもの（担当候補一意等）＝坪井さん即断」「人の記憶が要るもの（担当候補なし等）＝部長確認会へ」の2経路
- **キュー滞留はSTOの主要KPI**。週次レビューで残件数を必ず確認する

### 6-3. 財務データの受け渡し（柳沼さんライン）

- 定期供給：取引先別売上明細（頻度は初回受領後に月次で合意）、作品別グロス＋委員会別配分率、親セグメント⇔作品対応表
- 受領→反映：坪井さんが名寄せキー経由で一括流し込み（手入力はしない）。反映後、金曜レビューで鮮度を報告
- 粗利算定：2層方式（案件レベル＝NXグロス×作品別実効率／全社レベル＝財務純額）。実効率テーブルの整備・検証は柳沼さんと坪井さんの共同作業

### 6-4. スコアリング運用

- 5軸の採点定義（採点定義シート）を唯一の基準とする。基準の変更はL4（戦略会議）マター
- 「取引実績」軸は金額データから自動判定。他4軸は部長・分科会の判断（STOは判断しない）
- 採点開始の条件：**財務列（年間取引額・粗利・直近取引年）の充填完了後**。空のまま採点を始めない

## 7. 会議運用ルール（STO視点）

- 各会議の型・アジェンダ・議事録様式は既存の会議運用設計書に従う（本書では重複定義しない）
- STOの責任は「①資料が前日までに揃っている ②論点が明確である ③宿題が起票され期限が付いている ④次回冒頭で前回宿題を確認する」の4点
- 宿題は必ず「誰が・何を・いつまでに」の3点セットで起票（宿題管理シート）。主語が組織名の宿題は起票不可（必ず個人名）

## 8. STO自身の運営KPI（週次レビューで確認する数字）

| KPI | 目標 | 検知方法 |
|---|---|---|
| 要確認キュー残件数 | 週次で純減、90日で恒常的にゼロ近傍 | マスターの003シート件数 |
| 宿題消化率 | 期限内消化80%以上 | 宿題管理シート |
| 宿題の停滞 | 停滞5日超ゼロ | 停滞日数の自動計算 |
| データ鮮度 | マスター更新が週1回以上 | 再加工日時 |
| 会議の定時運転 | 分科会・戦略・点検の欠測ゼロ | 会議カレンダー |

※これはSTOの運転計器であり、改革本体のKPI（北極星＝粗利/営業工数 ほか）はKPIワークブックで別管理。

## 9. 増員のトリガー（この3条件が来るまで4名を維持）

1. **工数申告の集計が回り始めたら**（Day30以降）→ 集計・データクレンジング要員1名を坪井さんの下に
2. **撤退・縮小案件の交渉が始まったら** → 法務との兼務リエゾン1名
3. **海外領域の棚卸しが本格化したら** → 海外事業部から兼務1名（NX外データの捕捉役）

増員の判断はL3（新谷）。トリガー到来前の増員は行わない。

## 10. リスクと対策

| リスク | 対策 |
|---|---|
| 専任2名の二重負荷・燃え尽き | 専任化通知で部門業務を明示的に切る（3-2）。金曜レビューで負荷を毎週確認し、限界前にトリガー外増員もL3判断で可 |
| 属人化（坪井さんにしか分からないデータ処理） | 処理手順は必ずconfig・手順メモとしてマスター内に残す（既に実践されている方式を義務化） |
| 論点の内輪化 | 新谷の前日確認30分＋点検会議での会長の視点（3-3） |
| STOへの実行依頼の流れ込み | 「やらないこと」（2章）を部長会で明示し、依頼が来たら岡田さんがL2（部長）へ差し戻す |
| 財務データ供給の遅延 | 柳沼さんラインを兼務として体制に正式に組み込み（本書3章）、依頼ベースから定期供給へ切り替える |
