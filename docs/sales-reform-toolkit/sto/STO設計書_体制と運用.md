**作成：新谷隼人（専務執行役員）／営業改革事務局（社外秘・取扱注意）**
**位置づけ：営業改革グランドデザインの実行機関であるSTOの、体制・権限・運用のすべてを定める文書。運用資料は本書末尾の付属資料一覧を参照**

## 1. STOのグランドデザイン

### 1-1. ミッション

**成果目標（2026-07-16 指令・ベースライン確定）：本プロジェクトの成果として営業利益を予算に対して＋5億円とする（66期予算40.2億→着地45.2億。最新見込み比では＋6.25億のギャップ）。**レバー別の積み上げ設計・分科会への割付は `成果目標メモ_営業利益プラス5億.md` に定める。改革テーマの優先順位（キャパ上限の入れ替え判断）は、この5億への寄与額を基準とする。

STOは営業改革を**実行する部隊ではない**。実行するのは各部長と分科会である。STOの存在理由は次の3機能に限定する。

1. **データを回す** — 棚卸し・スコアリング・KPIの数字を、正しく・速く・止めずに供給する
2. **会議を回す** — 分科会×3・戦略会議・点検会議のサイクルを設計どおりに運転し、宿題を消化させる
3. **意思決定に上げる** — 現場で解けない詰まりを24時間以内にオーナーへ届け、役職の力で外す

### 1-2. 設計原則

- **最小人員で始める。** 専任1名（小沢）＋兼務3名（坪井・大塩・柳沼）＋オーナー。機能が先、人数は後。増員は本書9章のトリガー条件でのみ行う
- **STOは実行に手を出さない。** STOが案件対応を代行し始めると「事務局がやってくれる」構造になり、部長の当事者性が死ぬ。改革の主役は部長である
- **外部に依存しない。** 会議の型・論点設計は内製する。データ作業を外部に出すと社内にノウハウが残らない
- **工数把握は評価に使わない。** STOが集める工数データは資源配分の設計のためであり、個人評価には一切使用しない（グランドデザインの大原則をSTO運用でも堅持する）

### 1-3. 改革全体の中での位置

```
点検会議（会長）……………… 月次。改革が約束どおり進んでいるかの点検
    ↑ キーチャート5枚をSTOが作成
戦略会議（永竹社長）………… 隔週。分科会から上がる論点の意思決定
    ↑ アジェンダ・論点整理をSTOが準備（新谷が前日30分で事前確認）
分科会×3（黒澤・南谷・高橋）… 週次。接点づくり／ライセンス営業改革／経営基盤強化
    ↑ データ供給と宿題管理をSTOが担う
STO（本書）…………………… 日次。上記すべての運転席
```

## 2. スコープ — 対象領域と、やること・やらないこと

### 2-0. 改革の対象領域（2026-07 拡張）

対象は営業部門に閉じない。**制作 → 商品 → 流通 → プロモーション → ライブ → 営業（ライセンス・広告・海外）のバリューチェーン全体**を改革のスコープとする。

- 根拠：部長フィードバックで全部門から「自部門も対象」との認識が示された（宍戸さん「商品開発本部・カード開発部もスコープと認識」、橋本さん「作品・メディアディストリビューションを切り離すな」、石塚さん「製作企画と営業の情報流通」、菅野さん「部門間依頼のフロー整理」ほか）。IPの価値は制作で生まれ、接点で届く——**部門間の分断こそが本改革の対象**
- ただしSTOの3機能（データ・会議・意思決定接続）は不変。スコープが広がっても、STOが各領域の実行を代行することはない。各領域の実務論点は分科会と部長会で扱い、STOはそのデータと会議を回す
- 棚卸し・工数計測・評価軸の適用は営業領域から開始し、制作・商品・流通・プロモ・ライブへは分科会の設計進度に合わせて段階展開する（一斉適用による現場負荷の集中を避ける。山田さん・井上さんの指摘を反映）
- **監修改革を正式にスコープに含める**（2026-07-14決定）。営業時間の大半を占める監修・調整の構造改善と、ブランド判断の基準化（属人判断からの脱却）。詳細：`監修改革_論点メモ.md`

### 2-0b. キャパシティ上限（テーマの同時保有数）

2名の専任で改革テーマを無制限には持てない。上限を定め、超える場合は**入れ替え**でのみ受ける。

| 区分 | 内容 | 同時上限 |
|---|---|---|
| A | STOが深く設計・推進する重点改革 | **2件** |
| B | 部門主導でSTOが設計支援するテーマ | 3件 |
| C | KPI・進捗のみ監視するテーマ | 5件 |

- 新しいAテーマを追加する場合は、既存テーマを終了・停止・格下げする。「全部重要なので全部やる」は認めず、**止める案件は新谷が決める**
- 最初のAテーマは次の2件：**①営業全量棚卸しと顧客・案件・売上・利益のひも付け ②営業プロセス・会議体の再設計と監修・契約等のボトルネック改善**
- 接点づくりは部門側（黒澤さん）を実行主体とし、STOは重点顧客・パイプラインの監視（C相当）に留める

### 2-0c. STOへの依頼の受付条件（関所）

STOへの依頼は坪井さんが一本化して受け付ける。次の5点が揃わない案件は受けない（揃えるのは依頼側の責任）。

1. 解決すべき経営課題　2. 目標KPI　3. 部門側の責任者　4. 期限・判断日　5. 必要な経営判断

役員からの直接的な特急資料依頼も例外にしない（新谷経由で優先順位判断にかける）。

| | やること | やらないこと |
|---|---|---|
| データ | 棚卸しマスターの管理、名寄せ、財務データの流し込み、スコアリング運用、KPI算出 | データの「評価・判断」（採点の判断は部長・分科会が行う） |
| 会議 | 日程・アジェンダ・議事録・宿題管理、会議体の運用改善 | 会議での意思決定（決めるのは各会議体の議長） |
| 実行 | 詰まりのエスカレーション | 案件の実行判断、顧客対応、交渉の代行 |
| 制度 | 論点の整理と選択肢の提示 | 評価制度・組織改編の決定（経営会議マター） |

## 3. 体制

**決定状況：2026-07-16決定——体制は全枠確定。小沢さんを専任、経営企画から大塩さん、財務から柳沼さんをアサイン。坪井さんは専任から兼務に変更（同日変更。STO稼働枠は元部門と合意して明示的に確保する）。**

**位置づけ：本改革は円谷プロ単独ではなく、山本会長・ホールディングスがコミットする取り組みであり、HDグループ経営企画がSTOをサポートする（現場サポートにHD人材の投入も選択肢とし、円谷プロ現場の負荷を増やさない）。また、社内で並走する改革系プロジェクト（AI活用・営業強化等）はSTOに段階的に集約する方針。調整は丁寧に行い、「新たに増える負担」にはしない（詳細：`STO定例メモ_20260714.md`）。**

**構造（v2.1）：STOは「設計（専任）」と「統制（兼務）」の2リードで成立させる連邦型。** 小沢さんが「何を・なぜ・どう変えるか」を設計し、坪井さんが「誰が・いつまでに・どこまで実現するか」を統制する。部門長が実行し数値成果を出す。新谷が優先順位を決め障害を除去する。**売上・利益・実行責任を部門長からSTOへ移さないことが最重要原則。**

**坪井さんが兼務であることの帳尻（重要）**：統制業務はコア4つ（①棚卸しマスターの正本管理 ②確認会一覧と財務データ受入れ ③週次レビューでの運転計器報告 ④決定ログの正本管理）に限定する。日次の督促・エスカレーション運用は**小沢さん着任までは新谷が暫定代行**し、着任後にSTO内で再配分する。STO日次15分は坪井さんの兼務日程に合わせ週2〜3回でも可。

| 役割 | 人 | 専任/兼務 | 状態 | 責任範囲 |
|---|---|---|---|---|
| オーナー | 新谷（専務執行役員） | 兼務 | **確定** | 改革の方向・優先順位・重要判断。テーマの開始/中止、資源配分、障害の除去、トップ外交 |
| 変革設計リード | 小沢さん | **専任** | **確定** | 改革の「中身」：最上位課題と原因仮説、ヒアリングと事実検証、営業プロセス/案件評価/価格・MG/監修/契約の再設計、1ページ意思決定書、部門横断の合意形成、パイロット設計、標準化・部門移管 |
| 実行統制・データリード | 坪井さん | **兼務**（STO稼働枠を部門と合意して確保） | **確定** | 改革の「完遂」のコア：棚卸しマスターの正本管理・名寄せ、確認会一覧、財務データ受入れ、KPI・決定ログの正本管理、週次レビュー報告（日次の督促運用は小沢さん着任までは新谷が暫定代行） |
| 戦略サポート | 大塩さん（HD経営企画） | 兼務 | **確定** | 戦略面の支援：読み管理（確度定義）原案、経営向け論点整理の壁打ち、HDグループ経営企画との接続・並走プロジェクトの整理 |
| 財務リエゾン | 柳沼さん（財務） | 兼務（週2〜3時間） | **確定** | 財務データの定期供給（取引先別売上・作品別配分率）、粗利算定ルールの検証 |

**会議事務の扱い（重要）**：坪井さんを「会議事務局」にしない。議事録は作らず**決定・責任者・期限のみを決定ログに記録**（坪井さん所管）。日程調整は各会議の議長側で行い、STOは持たない。旧設計の「PMO・会議運営」専任枠は本v2で廃止し、機能を上記に分解した。

### 3-0. 成果の評価基準（2リード）

- 小沢さんの成果は「資料を作った」ではなく、**経営判断が成立した／業務が変わった／部門が自走した／利益・速度・品質が改善した**で評価する
- 坪井さんの成果は「会議を回した」ではなく、**ひも付け率・期限遵守率・エスカレーション速度・部門のデータ自走率**で評価する（8章のSTO固有KPI）

### 3-0b. 2名の工数配分と防衛ルール

| 小沢さん | 配分 | | 坪井さん | 配分 |
|---|---|---|---|---|
| 課題分析・改革設計 | 40% | | 統合計画・データ・ダッシュボード | 30% |
| パイロット・部門実装支援 | 25% | | 進捗・リスク・エスカレーション | 25% |
| 経営判断資料 | 15% | | 標準化・自動化 | 20% |
| 分科会・点検・戦略会議 | 15% | | 会議・意思決定管理 | 15% |
| 緊急対応・思考余白 | 5% | | 緊急対応・調整余白 | 10% |

- 各人の会議時間は**週8時間以内**。2人が同席する会議は**週4時間以内**（2人が全分科会に同席しない。分科会へは原則1名）
- 「一人が作り、もう一人がレビューする」。共同編集を常態化させない
- 稼働を100%埋めない。10%は重要課題への備えとして空ける
- 旧業務は専任開始時までに移管完了。やむを得ない引継ぎ支援は**4週間・週2時間以内**に限定

### 3-1. 各人の「やらないこと」

- **坪井さん**は会議調整をやらない。データに専念する
- **小沢さん**はデータ加工・議事録をやらない。課題設計と合意形成に専念する
- **新谷**は進捗管理をやらない。エスカレーションを受けて詰まりを外すことに専念する
- **柳沼さん**はSTOの定例に常時出席しない。データ受け渡しと算定ルール検証の必要時のみ

### 3-2. 専任化の条件（着任前に必ず実施）

**小沢さん（専任）**：元部門の部長に新谷から直接「90日間は改革専任とする。期間中の評価は改革への貢献で新谷が責任を持つ。部門業務は引き継ぐか停止する」を伝える。通知文面は付属資料②を使用。
**坪井さん（兼務）**：STO稼働枠（曜日・時間帯）を元部門の部長と新谷の三者で合意し、**明示的に切り出す**。「部門業務の上に暗黙で上乗せ」を認めない。STO業務が枠を超え始めたら、担務を減らすか増員するかを新谷が判断する（本人の我慢で吸収させない）。

### 3-3. 会議の型の内製（外部アドバイザーなしで回す設計）

- 会議の型は既に文書化済み（会議運用設計書・アジェンダテンプレート）。新規設計は発生しない
- 運用改善は坪井さんが金曜の週次レビューで回し、型の見直しは小沢さんが設計する
- **論点の質のチェックは新谷が戦略会議の前日に30分、アジェンダを事前確認して担保する**（新谷の定例工数として確保）
- 「論点が内輪の常識に寄る」リスクは、点検会議での会長の視点が外部の目の代替となる

## 4. 権限とエスカレーション

### 4-1. 決定権限の4段階

| レベル | 決められること | 決める人 |
|---|---|---|
| L1：STO内 | データ処理の手順、会議の運営方法、テンプレートの改訂 | 小沢さん／坪井さん |
| L2：部長 | 自領域の担当割り、顧客・案件の事実確認、ヒアリング対応 | 各部長 |
| L3：オーナー | 領域をまたぐ調整、期限の変更、リソースの一時投入、対外的な依頼 | 新谷 |
| L4：会議体 | スコアリング基準の変更、撤退・縮小の判断、評価制度・組織に関わる事項 | 戦略会議／経営会議 |

### 4-2. エスカレーションルール

- **基準：自分のレベルで24時間以内に解けないものは、抱えずに1つ上へ上げる**
- 経路：小沢さん・坪井さん → 新谷（チャット即時＋エスカレーションログ記録）→ 必要に応じ戦略会議の論点へ
- 上げ方の型：「①何が詰まっているか ②誰の判断が要るか ③放置すると何がいつ遅れるか」の3点を1メッセージで
- エスカレーションは失点ではない。**滞留こそ失点**として運用する（宿題管理シートの停滞日数で機械的に検知）

## 6. データ運用ルール

### 6-1. マスターの管理

- 正本は棚卸し・スコアリングマスター1ファイルのみ。**コピーを配布しない**（閲覧は共有リンク、編集は坪井さんと明示的に許可した者のみ）
- 作業用シート（_tsby等）は、部長確認が完了した時点で正版シートへ昇格し、旧サンプル版は削除する
- 変更履歴：週次更新の完了時に「再加工日時」を必ず更新（既にconfig化済みの運用を継続）

### 6-2. データパイプライン（確立済みの3層構造を標準とする）

```
原文保持（00_転記） → 機械加工（002_加工用・名寄せキー付与） → 要確認キュー（003_人の判断待ち）
```

- 機械で判断できないものは推測せず要確認キューへ落とす（理由コード付き）
- キューの解消は「事務局で解けるもの（担当候補一意等）＝坪井さん即断」「人の記憶が要るもの（担当候補なし等）＝部長確認会へ」の2経路
- **キュー滞留はSTOの主要KPI**。週次レビューで残件数を必ず確認する

### 6-3. 財務データの受け渡し（柳沼さんライン）

- 定期供給：取引先別売上明細（頻度は初回受領後に月次で合意）、作品別グロス＋委員会別配分率、親セグメント⇔作品対応表
- 受領→反映：坪井さんが名寄せキー経由で一括流し込み（手入力はしない）。反映後、金曜レビューで鮮度を報告
- 粗利算定：2層方式（案件レベル＝NXグロス×作品別実効率／全社レベル＝財務純額）。実効率テーブルの整備・検証は柳沼さんと坪井さんの共同作業

### 6-4. スコアリング運用

- 5軸の採点定義（採点定義シート）を唯一の基準とする。基準の変更はL4（戦略会議）マター
- 「取引実績」軸は金額データから自動判定。他4軸は部長・分科会の判断（STOは判断しない）
- 採点開始の条件：**財務列（年間取引額・粗利・直近取引年）の充填完了後**。空のまま採点を始めない

## 7. 会議運用ルール（STO視点）

- 各会議の型・アジェンダ・議事録様式は既存の会議運用設計書に従う（本書では重複定義しない）
- STOの責任は「①資料が前日までに揃っている ②論点が明確である ③宿題が起票され期限が付いている ④次回冒頭で前回宿題を確認する」の4点
- 追加ルール（v2）：**報告だけの案件は会議に載せない**／1会議で扱う重要論点は最大3件／事前資料は1ページ／**決めることがない会議は開催しない**（点検会議＝月次60分・山本会長議長は決議済みのため変更しない）
- 標準成果物は7つに限定し「唯一の正」とする：①改革チャーター ②テーマ統合バックログ ③KPIダッシュボード ④顧客・案件・売上・利益マスター ⑤決定・アクション・リスクログ ⑥1ページ意思決定書 ⑦効果測定・部門移管シート。**同じ数字をExcelとPowerPointへ重複転記させない**
- 宿題は必ず「誰が・何を・いつまでに」の3点セットで起票（宿題管理シート）。主語が組織名の宿題は起票不可（必ず個人名）

## 8. STO自身の運営KPI（v2）

**原則：会議数・資料数・タスク数はKPIにしない。**「STOが忙しいこと」は成果ではない。

### 8-1. STO固有KPI（暫定目標）

| KPI | 目標 |
|---|---|
| 顧客・案件・売上の金額ベースひも付け率 | 30日で80%、60日で95% |
| 重要案件の責任者・期限・次アクション設定率 | 100% |
| 重要アクションの期限遵守率 | 90%以上 |

| 部門自身によるデータ更新率 | 90日で80%以上 |

### 8-2. 日常の運転計器（金曜の週次レビューで確認）
