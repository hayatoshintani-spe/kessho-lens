# 営業改革 実行ツールキット（運用ガイド）

**作成者：円谷プロダクション 専務執行役員 新谷 隼人（本改革スポンサー）**
**管理者：Sales Transformation Office（STO）**

営業改革グランドデザイン（`../sales-transformation-grand-design.md` / 同名PPTX）を**実際に回すための運用ツール一式**です。承認当日（Day 1）からExcelで運用を開始し、Month 2〜3でNotionへ移行できる構成になっています。

---

## 1. ツールキット全体マップ

```
sales-reform-toolkit/
├── README.md                            ← 本ファイル（運用ガイド）
├── 01_棚卸し・スコアリングマスター.xlsx   ← 中核DB：5つの棚卸し＋自動スコアリング（STOが管理）
├── 02_工数申告_週次テンプレート.xlsx      ← 営業担当者が週15分で入力（1人1ファイル）
├── 03_KPI・会議運営・90日WBS.xlsx        ← KPI・決定ログ・会議アジェンダ・90日タスク（STOが管理）
├── templates/
│   ├── 経営キックオフ宣言文案.md          ← Day 3までに経営陣名義で全社発信する文面
│   ├── 会議アジェンダ・議事録テンプレート.md ← 週次／月次／四半期の運営フォーマット
│   └── トップ外交48時間登録メモ.md        ← 経営陣が面談後に送る1分メモの型
└── notion/
    ├── Notion構築ガイド.md               ← DB設計書（プロパティ・数式・ビュー・権限）
    └── csv/                             ← Notionにそのままインポートできる9つのDB雛形
```

## 2. ツール選択の指針（Excel → Notion）

| フェーズ | 推奨ツール | 理由 |
|---|---|---|
| Day 1〜30（棚卸し） | **Excel（本キット01・02）** | 即日開始できる。既存データからSTOが下書きを作る作業もExcelが最速 |
| Day 31〜60（評価・MVP） | Excel継続＋**Notion構築開始** | スコアリング・トリアージはExcelの数式で運用しつつ、NotionをCSVインポートで立ち上げる |
| Day 61〜90（意思決定運用） | **Notionへ移行**（Excelは工数申告のみ残す選択も可） | 3層ダッシュボード（ビュー権限分け）、会議のその場更新、モバイル入力はNotionが優位 |
| Month 6〜 | SFA/CRM投資判断ゲート | Notion運用の実績データを基に、本格SFA/CRMへの投資を判断（運用が先、ツールが後） |

**原則：ツールの乗り換えでデータ構造は変えない。** 本キットのExcel列とNotion CSVの列は同じ設計にしてあるため、コピー&ペーストで移行できます。

## 3. 運用サイクル（誰が・いつ・何を）

### 毎日（担当者：1〜2分）
- 動きのあった案件の「次アクション」「最終更新日」を更新（01のExcel or Notion案件DB）

### 毎週（合計15〜30分）
| 曜日 | 誰が | 何を |
|---|---|---|
| 金曜 or 月曜朝 | 営業担当者 | 工数申告（02のExcel）を記入しSTOへ提出（15分以内） |
| 月曜 | STO | 停滞案件・期限超過を抽出し、週次パイプライン会議のアジェンダを自動生成 |
| 週次会議（30分/領域） | マネージャー＋担当 | 重点商談・停滞案件の次アクション決め。資料作成禁止、マスタを直接投影 |

### 毎月
| タイミング | 誰が | 何を |
|---|---|---|
| 会議前営業日 | STO | 01マスタの締め、トリアージ候補の起案書作成、03のKPI更新 |
| 月次ポートフォリオ会議（90分） | 経営陣＋部門長＋STO | 標準アジェンダ（03のシート）通りに、撤退・省力化・経営支援を**決定**。決定ログに記録 |
| 会議後48時間 | STO | 決定ログの展開、担当者への通知、外交逆提案の更新 |

### 48時間ルール（経営陣）
- トップ外交の面談後48時間以内に、`templates/トップ外交48時間登録メモ.md` の型でSTOへ送る（口頭・音声メモ可）。記録化・追跡はSTOが行う

## 4. 役割分担（RACI要約）

| 作業 | 経営陣（新谷） | STO | マネージャー | 担当者 | 監修・法務 |
|---|---|---|---|---|---|
| 棚卸しの下書き作成 | I | **R** | C | C | - |
| 案件・顧客データの更新 | I | A | C | **R** | - |
| 工数申告 | I | A（集計） | C | **R** | - |
| スコアリング・ランク付け | A（ウェイト決定） | **R** | C | C | - |
| トリアージ起案 | A（決定） | **R** | C | I | - |
| 撤退・省力化・経営支援の決定 | **R/A** | 起案 | C | I | - |
| リードタイム計測・プロセス改革 | A | C | C | I | **R**（WG） |
| 決定ログ・KPI更新 | I | **R** | C | I | - |

R=実行 A=承認 C=協議 I=共有

## 5. 運用ルール10か条

1. **工数データは人事評価に使わない**（経営宣言文書に明記。違反したら改革は死ぬ）
2. 次アクションと期限のない案件を作らない（登録時に必須）
3. 停滞（30日）・期限超過は自動でアジェンダに載る。恥ではなく、支援のシグナルとして扱う
4. 会議のための資料は作らない。マスタ／ダッシュボードを直接投影する
5. 決定したことは必ず決定ログへ。翌回冒頭で実行確認する
6. 撤退・省力化の起案はSTOが行う。現場担当者を「言い出しっぺ」にしない
7. トップ外交は面談後48時間以内に登録。初動は30日以内
8. 新規成長領域（D2C・CRM・海外・AI・教育・カードゲーム・新カテゴリ）は月次会議の固定枠で必ず扱う
9. サンプル行・仮の数値は「（サンプル）」「仮」と明記し、実データと混ぜない
10. 入力負荷が週15分を超えたら、現場ではなく仕組み側を直す（STOに申告）

## 6. 導入手順（Day 1〜7）

1. **Day 1**：経営会議で9項目承認 → STOメンバー確定
2. **Day 2**：STOが `01_棚卸し・スコアリングマスター.xlsx` の「マスタ設定」を自社仕様に調整（担当者リスト・ウェイト・閾値）。共有ドライブに配置し編集権限をSTO＋マネージャーに設定
3. **Day 3**：`templates/経営キックオフ宣言文案.md` を経営陣名義で全社発信
4. **Day 4〜5**：`02_工数申告_週次テンプレート.xlsx` を営業全員に配布（1人1ファイル、ファイル名「工数申告_氏名.xlsx」）。説明会15分×領域ごと
5. **Day 5〜7**：STOが請求・契約データから顧客・案件リストの下書き投入を開始。`03_KPI・会議運営・90日WBS.xlsx` の90日WBSで進捗管理を開始
6. **並行**：Notion移行を予定する場合は `notion/Notion構築ガイド.md` に沿ってワークスペースを準備（Day 31〜で本格化）
