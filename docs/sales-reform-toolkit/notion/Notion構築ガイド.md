# Notion構築ガイド — 営業改革ワークスペース設計書

STOがNotionで営業改革の運用基盤を構築するための設計書です。`csv/` フォルダの9ファイルをインポートすれば、データベースの骨格は10分で立ち上がります。プロパティ型の調整・リレーション・数式・ビューは本書に従って設定してください。

**所要時間目安：初期構築 半日／権限・ビュー調整 半日**

---

## 1. ワークスペース構造

```
🏢 営業改革（トップページ）
├── 📌 はじめに（7つの基本思想・運用ルール10か条・経営宣言文を掲示）
├── 📊 経営ダッシュボード          ← 経営陣向け（月次会議で投影）
├── 📈 マネージャーダッシュボード   ← 領域別（週次会議で投影）
├── ✅ マイページ（担当者用テンプレ） ← 各自の案件・今週のアクション
├── 🗃 データベース
│   ├── 顧客DB
│   ├── 案件DB（中核）
│   ├── パートナーDB
│   ├── トップ外交DB
│   ├── 休眠顧客DB
│   ├── 工数ログDB
│   ├── 決定ログDB
│   ├── 90日タスクDB
│   └── KPI DB
└── 📁 会議室（議事・決定の記録ページ。決定はすべて決定ログDBへ）
```

## 2. 構築手順

1. トップページ「営業改革」を作成し、上記構造の空ページを用意
2. `csv/` の9ファイルを各DBページに **Import → CSV** で取り込む（文字コードはUTF-8 BOM付きなのでそのまま読める）
3. 本書 §3 に従い、各DBのプロパティ型を変更（インポート直後はすべてテキストになっているため）
4. §4 のリレーションとロールアップを設定
5. §5 の数式プロパティを追加
6. §6 のビューを作成し、§7 の権限を設定
7. サンプル行（「（サンプル）」表記）は実データ投入後に削除

## 3. データベース設計（プロパティ定義）

### 3.1 案件DB（中核）
| プロパティ | 型 | 設定 |
|---|---|---|
| 案件名 | タイトル | - |
| 顧客 | リレーション | → 顧客DB |
| 営業領域 | セレクト | ライセンス／自社MD／リテール／イベント／海外／カードゲーム関連／広告・タイアップ／D2C・CRM連動／新規事業／教育・須賀川関連／AI協業／トップ外交 |
| 担当者 | ユーザー | - |
| ステージ | セレクト | リード／商談／提案／条件合意／監修・契約／立ち上げ・運用 |
| 確度 | セレクト | 高（75%以上）／中（50%）／低（25%）／初期（10%） |
| 金額見込(千円)・粗利見込(千円)・想定総工数(h) | 数値 | - |
| 売上〜ブランドの7スコア | 数値 | 1〜5で入力 |
| 次アクション | テキスト | **必須運用** |
| 期限 | 日付 | - |
| 最終更新日 | 最終更新日時 | 自動 |
| トップ外交由来 | チェックボックス | - |
| 監修トラック | セレクト | フル監修／ファストトラック／事後サンプリング（Day 61〜で追加） |
| 工数実績 | ロールアップ | 工数ログDB→時間(h)の合計 |

### 3.2 その他DB（要点のみ）
- **顧客DB**：関係状態（セレクト：活発／維持／休眠）、5スコア（数値）、ランク確定（セレクト：S/A/B/C）、最終接触日（日付）、案件（リレーション逆方向・自動）
- **トップ外交DB**：面談日（日付）、状態（セレクト：登録／アサイン済／初動済／案件化／提案／契約／消滅／保留）、担当営業・スポンサー役員（ユーザー）、初動実施日（日付）、関連案件（リレーション→案件DB）
- **工数ログDB**：日付（日付）、担当者（ユーザー）、案件（リレーション→案件DB）、活動分類（セレクト：10分類）、時間(h)（数値）
- **決定ログDB**：会議体（セレクト）、決定区分（セレクト：撤退／省力化／重点化／経営支援／ルール変更／その他）、責任者（ユーザー）、期限（日付）、状態（セレクト：未着手／進行中／完了／保留）
- **90日タスクDB**：フェーズ（セレクト：Day 1-30／31-60／61-90）、状態（セレクト）、期限（テキストのままでも可）
- **KPI DB**：区分（セレクト）、ベースライン・目標・直近実績（数値 or テキスト）、状態（セレクト：計測設計中／計測中／改善／悪化）

## 4. リレーションとロールアップ

| 接続 | 効果 |
|---|---|
| 案件DB ↔ 顧客DB | 顧客ページで全案件を一覧。顧客の年間粗利をロールアップ |
| 案件DB ↔ 工数ログDB | 案件の**工数実績**を自動集計 → 「実績 粗利/工数」数式の材料 |
| 案件DB ↔ トップ外交DB | 外交由来案件の追跡（トップ外交案件化率の分子） |
| 決定ログDB → 案件DB | 撤退・省力化・経営支援の決定を案件に紐付け |

## 5. 数式プロパティ（コピー用）

**案件DB「総合スコア」**（100点満点。ウェイトを変える場合は係数を修正）
```
round((prop("売上スコア")*0.15 + prop("粗利スコア")*0.20 + prop("工数効率スコア")*0.15 + prop("戦略スコア")*0.15 + prop("CRMスコア")*0.10 + prop("海外スコア")*0.10 + prop("ブランドスコア")*0.15) * 20 * 10) / 10
```

**案件DB「案件区分」**
```
if(empty(prop("総合スコア")), "", if(prop("総合スコア") >= 80, "S：経営支援", if(prop("総合スコア") >= 65, "A：重点", if(prop("総合スコア") >= 50, "B：標準", "C：省力化・撤退検討"))))
```

**案件DB「停滞」**（最終更新から30日超）
```
if(dateBetween(now(), prop("最終更新日"), "days") > 30, "🔴 停滞", "")
```

**案件DB「実績 粗利/工数」**（工数ログのロールアップ後）
```
if(prop("工数実績") > 0, round(prop("粗利見込(千円)") / prop("工数実績") * 10) / 10, toNumber(""))
```

**トップ外交DB「初動期限」「期限アラート」**
```
dateAdd(prop("面談日"), 30, "days")
```
```
if(and(empty(prop("初動実施日")), now() > dateAdd(prop("面談日"), 30, "days")), "🔴 期限超過", "")
```

## 6. ビュー設計（3層ダッシュボードの実装）

### 経営ダッシュボード（ページに案件DB等のリンクドビューを並べる）
| ビュー | 元DB | フィルタ／表示 |
|---|---|---|
| ポートフォリオ（ボード） | 案件DB | グループ＝案件区分、カードに金額・粗利・工数 |
| 意思決定キュー | 案件DB | 案件区分=C or 停滞=🔴 or 高工数低収益。テーブル表示 |
| 経営支援案件 | 決定ログDB | 決定区分=経営支援、状態≠完了 |
| トップ外交パイプライン | トップ外交DB | ボード：グループ＝状態 |
| 新規成長領域（固定枠） | 案件DB | 営業領域 in（D2C・CRM連動／海外／AI協業／教育・須賀川関連／カードゲーム関連／新規事業） |
| KPI一覧 | KPI DB | テーブル、状態で色分け |

### マネージャーダッシュボード（領域ごとに複製）
- パイプライン（ボード：ステージ別、フィルタ＝自領域）
- 停滞・期限超過（テーブル：停滞=🔴 or 期限<今日）
- チーム工数（工数ログDB：グループ＝担当者、期間フィルタ＝今週）
- S/A顧客カバレッジ（顧客DB：ランク in S,A、最終接触日 昇順）

### マイページ（担当者テンプレート）
- 今週のアクション（案件DB：担当者=自分、期限 昇順）
- 自分の案件（ボード：ステージ別、担当者=自分）
- 待ち状態（案件DB：担当者=自分、ステージ=監修・契約）※「待ち」を本人の責任から切り離して見せる
- 週次工数入力（工数ログDB：担当者=自分、テンプレートボタンで1行追加）

## 7. 権限設計

| 対象 | 権限 |
|---|---|
| STO | 全DBフルアクセス（構造変更はSTOのみ） |
| 経営陣 | 全ページ閲覧＋決定ログ・トップ外交DB編集 |
| マネージャー | 自領域ページ編集、全体閲覧 |
| 担当者 | 案件DB・工数ログDB・顧客DBの編集、マイページ |
| 個人の工数明細 | **本人とSTOのみ閲覧**（マネージャー以上には集計値のみ共有）— 監視感の排除。Notion標準機能では行単位権限が難しいため、工数ログDBを人別に分けるか、集計ページのみ共有する運用で担保 |

## 8. 運用の自動化（任意・Notion有料プラン）

- **オートメーション**：案件のステージが「監修・契約」に変わったら監修担当へ通知／期限超過で担当者へリマインド
- **定期テンプレート**：月次会議ページを毎月1日に自動生成（標準アジェンダ入り）
- **Slack連携**：決定ログ追加時に営業チャンネルへ通知
- **API連携（Month 4〜）**：工数ログの集計をKPI DBへ自動反映。将来のSFA/CRM移行時のデータ出口としてもAPIを使う

---
*ウェイト・閾値（0.15等・80/65/50点・30日）はExcel版「マスタ設定」と同一。変更時は両方を揃えること。*
