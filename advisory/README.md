# AI経営参謀システム（参謀本部）— 運用マニュアル

新任役員のための、Claude Code ネイティブな個人AI参謀群。
単なるチャットではなく、**役割を持った専門参謀 × 定型ワークフロー × 蓄積されるナレッジ**で、
「毎朝の意思決定」から「役員メモ」「案件評価」「提案作成」までを一気通貫で支える。

---

## 全体像

```
kessho-lens/
├── .claude/
│   ├── agents/        # 10体の専門参謀（サブエージェント）
│   └── commands/      # 9個のスラッシュコマンド
└── advisory/          # あなたの思考が蓄積されるワークスペース
    ├── knowledge/     # 全参謀が読む共通前提（★まず最初に埋める）
    ├── templates/     # メモ・評価・提案・ログのひな型
    ├── 00_plan/       # 導入7日計画
    ├── 01_daily-brief/    # 毎朝のブリーフ出力
    ├── 02_issues/         # 経営論点整理
    ├── 03_ip-strategy/    # ウルトラマンIP成長戦略
    ├── 04_d2c-crm-experience/  # D2C/CRM/体験
    ├── 05_b2b-proposals/  # 大企業向け提案
    ├── 06_bizdev-deals/   # 事業開発案件評価
    ├── 07_finance/        # ファイナンス・競合比較
    ├── 08_org-talent/     # 組織・人材
    ├── 09_board-memos/    # 会長・社長・役員向けメモ
    └── 10_decision-log/   # 意思決定ログ
```

## 参謀とコマンドの対応

| やりたいこと | コマンド | 主担当参謀 |
|---|---|---|
| 毎朝の経営ブリーフィング | `/morning-brief` | sanbo-cho |
| 経営論点の整理 | `/issue-map <テーマ>` | sanbo-cho + 各専門参謀 |
| ウルトラマンIP成長戦略 | `/ip-strategy <論点>` | ip-strategist |
| D2C/CRM/体験の戦略仮説 | （`/issue-map` か直接指名） | d2c-crm-strategist |
| 大企業向け提案作成 | `/proposal <相手> <狙い>` | b2b-dealmaker |
| 事業開発案件の評価 | `/deal-eval <案件>` | bizdev-evaluator + red-team |
| ファイナンス/ROE/株価/競合 | `/finance-check <テーマ>` | cfo-analyst |
| 組織・人材・採用・評価 | `/org-review <論点>` | org-talent-advisor |
| 役員向け論点メモの清書 | `/board-memo <宛先> <テーマ>` | board-memo-writer |
| 意思決定の記録 | `/decision-log <決定>` | decision-logger |
| 重い判断の反論・穴探し | （各コマンドが自動起用／手動指名） | red-team |

> 特定の参謀を直接指名したいときは「ip-strategist として〜」のように話しかければよい。
> Claude が description を見て自動で適切な参謀に振ることもある。

## 運用リズム（推奨）

- **毎朝（5分）**: `/morning-brief` → 今日の一点集中を決める。
- **論点が来たら**: `/issue-map` で構造化 → 必要なら専門参謀に深掘り。
- **案件が来たら**: `/deal-eval`（red-team込み）→ 判断したら `/decision-log`。
- **役員に上げる前**: 分析を `/board-memo` で清書。
- **提案が要るとき**: `/proposal`。
- **週次（30分）**: `knowledge/my-mandate.md` の最重要論点TOP3を更新。動いている論点を棚卸し。
- **四半期**: 決算で `company-profile.md` `competitors.md` を更新。意思決定ログを事後レビュー。

---

## 使い始める前に（最重要）

**`advisory/knowledge/` を埋めることが全ての土台。** ここが空だと参謀の出力は一般論になる。
最低でも `my-mandate.md`（自分の役割・KPI・持論）を最初に埋めること。
7日間の具体手順は `advisory/00_plan/7day-plan.md` を参照。

---

## 設計思想（なぜこの形か）

1. **参謀は「役割」で分ける** — 1人の万能AIより、立場の違う専門家に議論させた方が死角が減る。特に red-team（反対役）を制度として組み込む。
2. **ナレッジは資産** — `knowledge/` に前提を貯めるほど、毎回の出力精度が上がる。会話は消えるが、ファイルは残る。
3. **意思決定を残す** — `decision-log` で「なぜそう決めたか」を記録し、判断の質を長期で高める。
4. **捏造しない規律** — 財務・市場数値は一次情報で裏取り。事実/仮説/未確認を必ず分ける。上司の信用を守る。
5. **1枚で意思決定** — 長いレポートより、貼ってすぐ動ける Markdown。

## セキュリティ / 機密の扱い

- 人物評価・未公表の数値・提携交渉など機密は `advisory/` 配下に置く。
- git にコミット/プッシュする前に機密性を確認する。社外秘を公開リポジトリに載せない。
- 外部送信（メール等）を伴う操作は必ず内容を確認してから実行する。
