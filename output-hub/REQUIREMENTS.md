## 1. 背景・目的

### 1.1 背景
Claude Code を使って多数のサイト・ツール・業務システム（ポーカー系ダッシュボード、TENTSUANA BASE 関連、ふりそで予約システム等）を制作してきたが、それらが各デプロイ先（Cloudflare Pages / Workers、Vercel、独自ドメイン）に散在しており、**「何を・どこに・どのURLで公開したか」を一望できる場所がない**。

### 1.2 目的
制作した公開サイト／プロジェクトを **1ページで一覧・検索・整理できる個人用ショーケース** を提供し、
- 過去の成果物の所在（URL・リポジトリパス）を即座に引ける
- 使用技術・カテゴリ・公開状況をひと目で把握できる
状態をつくる。

### 1.3 ゴール（到達点の定義）
本プロジェクトの到達点は **「個人用ショーケース（一覧・検索中心）」** とする。
死活監視・自動連携・アクセス解析・多人数共有などの「本格的な管理システム」は **スコープ外**（将来拡張として §9 に整理）。

---

## 2. スコープ

### 2.1 対象に含むもの（In Scope）
- 成果物の一覧カード表示（スクリーンショットのデザイン踏襲）
- 名前・説明・タグ・パス横断のインクリメンタル検索
- カテゴリ／ステータスによる絞り込み
- 並び替え（名前・カテゴリ・登録順 など）
- 集計サマリー（総数・公開中数・カテゴリ数）
- `sites.json` の手動編集によるデータ管理
- 限定公開でのデプロイ

### 2.2 対象に含まないもの（Out of Scope）
- ログイン／会員管理／多人数編集
- ブラウザ上の管理画面（フォーム追加・編集）
- バックエンド／データベース
- 死活監視・稼働率計測・アクセス解析
- GitHub／デプロイ先との自動同期
- メモ／TODO／更新履歴の保持
- 自動スクリーンショット／OGP取得

> 上記は将来必要になった時点で別フェーズとして再定義する。

## 3. 想定ユーザー・利用シーン

| 項目 | 内容 |
|---|---|
| 主ユーザー | 本人（制作者）1名 |
| 公開範囲 | **自分だけ**（非公開／限定公開） |

| 典型シーン | ・「あのダッシュボードのURL何だっけ」を即引き<br>・取引先に見せる前に該当サイトを探す<br>・新しく作ったサイトを1件追記して棚卸し |

## 4. 機能要件

| ID | 機能 | 要件 | 優先度 |
|---|---|---|:--:|
| F-01 | 一覧表示 | `sites.json` の全件をカードグリッドで表示する。カードには アイコン / 名前 / ステータスバッジ / 説明 / 公開URL（別タブ） / リポジトリパス / 技術タグ を表示する。 | 必須 |
| F-02 | 検索 | キーワード入力で 名前・説明・カテゴリ・タグ・パス を横断的に絞り込む（インクリメンタル、大文字小文字区別なし）。 | 必須 |
| F-03 | カテゴリ絞り込み | データから自動抽出したカテゴリチップで絞り込む。「すべて」を含む。 | 必須 |
| F-04 | ステータス絞り込み | `公開中 / 開発中 / 停止中 / 非公開` での絞り込み。 | 推奨 |
| F-05 | 並び替え | 登録順 / 名前(あいうえお・ABC) / カテゴリ / ステータス で並び替え。 | 推奨 |
| F-06 | 集計サマリー | 総数・公開中数・カテゴリ数を上部に表示する。 | 推奨 |
| F-07 | 件数表示 | 絞り込み結果の件数をセクション見出しに表示する。 | 必須 |
| F-08 | 空状態表示 | 検索/絞り込みヒット0件時にメッセージを表示する。 | 必須 |
| F-09 | データ管理 | `sites.json` の `sites` 配列に1件追記するだけでカードが増える。スキーマは §6 準拠。 | 必須 |
| F-10 | メタ設定 | ヘッダーのタイトル・サブタイトル・バッジ文言を `sites.json` の `meta` で変更できる。 | 任意 |
| F-11 | リンク遷移 | 公開URLは `target=_blank` / `rel=noopener` で別タブを開く。 | 必須 |

> F-04（ステータス絞り込み）・F-05（並び替え）は実装済み。F-04 はステータスが2種類以上ある時のみチップを表示する。

## 5. 非機能要件

| 分類 | 要件 |
|---|---|
| 性能 | 数十件規模を即時描画。初回表示は実質ネットワーク待ちのみ（ビルド/重い依存なし）。 |
| 保守性 | データ（`sites.json`）と表示（`index.html`）を分離。データ追加にコード変更不要。 |
| 移植性 | ビルド不要の静的ファイルのみ。Cloudflare Pages / Vercel / Netlify / GitHub Pages のいずれにもそのまま配置可能。 |
| 対応環境 | 最新版 Chrome / Safari / Edge / Firefox。スマホ幅で1カラムにフォールバック。 |
| 可用性 | 静的ホスティングに依存（サーバー運用なし）。 |
| セキュリティ | ユーザー入力を受け取らない。`sites.json` 由来の文字列は HTML エスケープして描画（XSS対策）。 |
| アクセシビリティ | テキストコントラスト確保、キーボードで検索・チップ操作が可能。 |
| 国際化 | 日本語 UI 固定。 |

### 5.1 限定公開の実現方式（要選定）
「自分だけ」を満たすため、以下のいずれかを採用する（推奨は上から）。
1. **Cloudflare Access（Zero Trust）** をサイト前段に設定し、自分のメールアドレスのみ許可（個人利用は無料枠）。
2. **Vercel のパスワード保護**（パスワード保護されたデプロイ）。
3. **推測困難なサブドメイン/パス**＋検索エンジン非収録（`robots.txt` で `Disallow`、`noindex`）。

> 静的サイト単体に認証機能は持たせず、ホスティング側の機能で限定公開を実現する。

## 6. データ仕様（`sites.json`）

```jsonc
{
  "meta": {
    "title":    "アウトプット一覧",                 // ヘッダー見出し
    "subtitle": "Claude Codeで作った…まとめて管理",  // サブテキスト
    "badge":    "PERSONAL-OUTPUT-HUB"               // 上部ラベル
  },
  "sites": [
    {
      "name":        "DOPAMINZOKU ポーカーダッシュボード", // 必須: カード見出し
      "icon":        "🎰",                                 // 任意: 絵文字（省略時 📄）
      "status":      "公開中",                             // 任意: 公開中/開発中/停止中/非公開
      "category":    "ポーカー",                           // 任意: 絞り込みチップに自動反映
      "description": "…ダッシュボード。…",                  // 任意: 説明文
      "url":         "https://dopaminzoku.pages.dev/",     // 任意: 公開URL（別タブ）
      "repoPath":    "ポーカー/poker-dashboard",           // 任意: 所在メモ
      "tags":        ["Cloudflare Pages", "Chart.js"]      // 任意: 技術タグ（配列）
    }
  ]
}
```

| フィールド | 型 | 必須 | 説明 |
|---|---|:--:|---|
| `name` | string | ◯ | サイト名 |
| `icon` | string |  | 絵文字アイコン |
| `status` | enum |  | `公開中`/`開発中`/`停止中`/`非公開`（バッジ色が変化） |
| `category` | string |  | カテゴリ（絞り込みに自動反映） |
| `description` | string |  | 説明文 |
| `url` | string(URL) |  | 公開URL |
| `repoPath` | string |  | リポジトリ内パス等のメモ |
| `tags` | string[] |  | 技術タグ |

## 7. 画面構成

単一ページ（SPA的に JS で描画）。上から順に：

1. **ヘッダー**（ダーク背景）: バッジ / タイトル / サブタイトル
2. **ツールバー**: 検索ボックス / カテゴリチップ / （並び替えセレクト ※F-05で追加）
3. **集計サマリー**: 総数・公開中・カテゴリ数
4. **セクション見出し**: 「🌐 公開サイト ◯件」
5. **カードグリッド**: 成果物カード（レスポンシブ、PCで3列／スマホで1列）
6. **空状態**: 0件時メッセージ
7. **フッター**: データ追加方法の案内

---

## 8. 受け入れ基準（Acceptance Criteria）

- [ ] `sites.json` の全件がカード表示される
- [ ] 検索語に対し、名前・説明・タグ・パスのいずれかが部分一致する件のみ表示される
- [ ] カテゴリチップ選択で該当カテゴリのみに絞り込まれ、「すべて」で解除される
- [ ] 並び替え操作で表示順が変わる（F-05実装後）
- [ ] ステータスごとにバッジ色が異なる
- [ ] 公開URLが別タブで開く
- [ ] `sites.json` に1件追記するだけで、コード変更なしにカードが増える
- [ ] スマホ幅で1カラム表示にフォールバックする
- [ ] `sites.json` 内の文字列に HTML を入れても、エスケープされそのまま描画されない（XSSが起きない）
- [ ] 限定公開設定（§5.1 のいずれか）が適用され、第三者がURL直打ちで閲覧できない

## 9. 将来拡張（スコープ外・参考）

現フェーズでは実装しないが、必要になった場合の候補：
- サムネイル／OGP プレビューのカード表示
- 各サイトのメモ／TODO／更新履歴（要データ保存）
- URL 死活監視による「公開中/ダウン」自動判定（要バックエンド or 外部監視）
- GitHub／Cloudflare／Vercel との自動同期での一覧生成
- ブラウザ上の管理画面（フォーム追加・編集）
- 一般公開ポートフォリオ化（SEO・OGP最適化）

---

## 10. 制約・前提

- データ登録は**手動**（`sites.json` 編集）を継続。Claude Code に「○○を一覧に追加して」と依頼することで追記する運用も可。
- バックエンド／DB を持たない静的構成を維持する。
- 機微情報（非公開URLの内部詳細等）を載せる場合は、限定公開（§5.1）を前提とする。
